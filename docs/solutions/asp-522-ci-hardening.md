# Learning: C11 help text and NATS PATH are not contracts

**Ticket:** ASP-522 (CI hardening continuation)

## Problem

Two brittle patterns in smoke tests and CI workflow:

1. **C11 `--help` output coupled to a specific string.** `smoke-test.sh` and `ci.yml` both ran `sandbox_run --help | grep -q built-in`. The help text is generated by the binary at build time and is not a documented contract — adding/removing flags or rewording help breaks the check even when the binary builds and functions correctly.

2. **NATS `gen accounts` check assumed nats-server on PATH.** `smoke-test.sh` ran `nats-server -c ... -t` to validate generated config, but only exported `$HOME/go/bin:/root/go/bin` which doesn't include `/usr/local/bin` (where CI/system installs place it). On hosts without nats-server, the check would fail noisily.

## Fix

- Replaced `grep -q built-in` with `>/dev/null 2>&1` for C11 help checks — verifies the binary exits 0 (it built and runs) without inspecting help text content.
- Added `/usr/local/bin` to PATH for the gen-accounts check, and wrapped with `command -v nats-server` guard that gracefully skips when the binary is absent.
- Added `tests/test_ci_assertions.py` as a contract regression test: asserts neither file uses `grep -q built-in`, and the gen-accounts line includes both the PATH fix and the guard.

## Key insight

Shell-level honor tests for binary artifacts should verify the binary *exists and runs* (exit code), not what its help text *says*. Help text is an output of the build, not a documented API. When adding pipeline checks, prefer `--help >/dev/null` over `--help | grep -q`.

# ASP-377: F-013 — Model digest pinning and post-pull verification

**Status:** READY_FOR_AIDER_QA
**Mode:** IMPLEMENTATION

## Summary

All model pulls were tag-only (`ollama pull granite8:latest`), so a compromised
registry or a MITM'd mirror could silently swap a model between installs. F-013
(LOW) asked for sha256 pinning. This change pins every `config/models.yaml`
upstream to an OCI-manifest sha256 digest in `config/models-digests.yaml` and
makes every consumer verify the *installed* revision against that pin —
fail-hard in install, fail-closed in health-check and dashboard.

## Key insight: this fleet's Ollama rejects `@sha256:` refs — pin by verify, not by ref

Verified on Ollama 0.32.11: `ollama pull name:tag@sha256:<x>`,
`ollama show name@sha256:<x>`, and `Modelfile FROM name@sha256:<x>` all fail
with `Error: 400 Bad Request: invalid model name` / `invalid model name`. The
digest-immutable refs the OCI/containers world expects simply do not exist here.

So the enforceable equivalent is **pull by tag, then verify-after-pull**:
- `install-models.sh` pulls `name:tag`, then asks the resolver to confirm the
  locally installed manifest is byte-equal (by sha256) to the committed pin;
  mismatch → `FATAL` exit 1, and `packaging/install-starship.sh` no longer
  swallows that exit code.
- Pins live in `config/models-digests.yaml`, generated by a single source of
  truth: `scripts/resolve-model-digests.py`.
- `config/models/Eve-V2-Unleashed.Modelfile` still uses `:latest` (the runtime
  has no tagged-digest ref) but its header documents the pinned digest and the
  pins file, so a future Ollama with `@sha256:` can tighten the `FROM`.
- The health checker and dashboard treat a missing/mismatched revision as
  tampered: no load, no auto-fix, digest parameters canonicalized so a
  legitimately-pinned model never false-flags.

## Second insight: `/api/tags` digests are bare hex, pins are `sha256:` — canonicalize

`curl /api/tags` on this fleet returns digests *without* the `sha256:` prefix.
Every direct string compare of "bare hex vs `sha256:…`" fails. All three
consumers canonicalize (add/normalize the `sha256:` prefix) before comparing;
the resolver's `canon_digest()` is the shared pattern.

## Design decisions

| Decision | Why |
|----------|-----|
| **Local-first resolution, registry fallback** (`resolve-model-digests.py`: local manifest store → `/api/tags` → `registry.ollama.ai` manifest API) | Pins the revision a cell actually owns and verifies against; registry used only for models not yet present so fresh cells get a resolvable known-good pin |
| **Drift is WARN, not tamper** | A cell may legitimately run an older pinned revision than the registry's current HEAD (e.g. Eve local `4d1fe4…` vs registry `dac84c6…`): `--check` reports it as a warning, and only `--strict`/`STARSHIP_STRICT_DIGESTS=1` turns it into an error |
| **`--check` offline = structural, online = drift** | CI/nightly must be deterministic (offline); a human on an online cell sees `ERROR` when registry tag ≠ pin, `WARN` when registry unreachable |
| **Fail-closed remediation** | Tampered/missing /api/tags entries still fail; resolver never returns a *wrong* digest, it returns nothing (exit ≠ 0) |
| **Env-driven paths, no hardcoded cell paths** | `STARSHIP_MODELS_YAML` / `STARSHIP_PINS_YAML` / `STARSHIP_PROFILES_YAML` / `STARSHIP_OFFLINE` / `STARSHIP_STRICT_DIGESTS` / `OLLAMA_URL` / `OLLAMA_MODELS` keep fixtures hermetic in tests |

## Changes

### New: `scripts/resolve-model-digests.py`

One source of truth for pins. Subcommands: default (resolve `config/models.yaml`
→ write/update pins), `--check` (offline structural or online drift),
`--digest NAME` (print pin, exit 1 if unpinned), `--verify-local NAME`
(exit 0 verified / 1 mismatch / 2 absent / 3 unpinned). Resolves the local
revision first — sha256 of the stored `registry.ollama.ai` manifest, or the
`/api/tags` digest — and falls back to the OCI manifest API for models not yet
present. `DIGEST_RE = ^sha256:[0-9a-f]{64}$`.

### New: `config/models-digests.yaml`

All 7 models pinned, `resolved: true` (sha256 manifest digests — local store
where present, registry HEAD fallback), `version: 2.1-f013`. Examples:
granite4.1-8b `sha256:4b7d9eae0407925a746a6723b479cc1f780878bdce255c2ee1b669ded31b9f55`
(its local ID is `4b7d9eae0407…`); Eve-V2-Unleashed
`sha256:dac84c6ab699dc0e6a1fd19144cb6f56a7f22b4b5ac694cdaef51124981f3124`.

### `scripts/install-models.sh`

Pulls by tag, then resolver `--verify-local` per model; FATAL on mismatch;
unpinned → WARN (dev) or FATAL when `STARSHIP_STRICT_DIGESTS=1`.

### `scripts/agent-health-checker.py` and `dashboard/server.py`

Load pins at startup (env `STARSHIP_MODELS_DIGESTS` → /etc → repo paths).
Health checker refuses to auto-fix a tampered revision (`SECURITY
MODEL-DIGEST-MISMATCH`). Dashboard: production pulls must supply a digest that
matches the pin; verifies after pull and removes a tampered model; audit-logs
unverified dev pulls. Canonical-digest comparison in both.

### `packaging/install-starship.sh`

`install-models.sh` no longer runs under `|| true` — digest failure stops the
install.

### `tests/test_model_digests.py` (17 hermetic tests)

Hermetic fixtures (fake `ollama` shim, hand-written manifest store, real
registry digests over `127.0.0.1` /api/tags where the model is legitimately
installed). Covers: committed pins validate + full coverage, generate/unresolved,
drift check rejects malformed pins, `--digest` fail-closed, aliases, verify-local
ok/absent/mismatch, install-models fail-hard + dev-WARN + strict-requires-pins,
health-checker canonicalization/mapping, dashboard pins loader + canonical
digest, install-starship doesn't swallow, resolver shebang. Start-time behavior
only — no production model touched.

### CI + nightly

`.github/workflows/ci.yml` job `security-model-digests` (offline strict
`--check` + fixture suite; `aiohttp` installed so the dashboard test runs);
`scripts/check-nightly.sh` Section 22 (resolver/pins coverage/Modelfile
documentation/guards/no-swallow/CI wiring + fixture tests). The original
"Modelfile `FROM @sha256:`" acceptance item is superseded by verify-after-pull
(deviation flagged for Architect review in `docs/plans/ASP-377.md`).

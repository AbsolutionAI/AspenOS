# Wed Aug 12 — First article inspection for software

## Draft post

Every machinist knows the rule: the **first article** is the most expensive piece you'll make. Not because the material costs more — because you're proving the process before you commit to the batch.

You set up the tool, run one part, pull it off the machine, and measure every critical dimension against the print. If it passes, the rest of the batch is free to run. If it fails, you fix the setup before making 500 bad parts.

We stole this for our agent fleet.

Before any new agent type goes live — before it gets a trigger, a budget, and a place in the pipeline — it runs a **first article shift**:

1. One real task, hand-selected to stress the inputs it's supposed to handle
2. One edge case it *wasn't* designed for (and should gracefully reject)
3. One human review of its output before it ever runs autonomously

If it passes all three, it's cleared for production. If it fails any, the agent spec gets revised — not silently patched, but spec'd again at the whiteboard.

The first article takes 10x longer than a normal agent launch. It has saved us roughly 100x in rework, late-caught errors, and confused downstream agents that consumed bad output.

The plant floor knew this for decades. Software is just catching up.

## 1. Problem

Decision recorded in [ASP-628](docs/plans/ASP-628-gatekeeper-packaging.md):
monorepo `src/python/gatekeeper/` is a **Plugin** (`aspen-gatekeeper`), profile-default
ON for actuator plants, **not** a second core-edge binary. No package skeleton exists yet —
the PACKAGES.md row names a production target that has no installable shape.

## 2. Success criteria

1. `plugins/aspen-gatekeeper/` package skeleton lands inside the aspen-os monorepo.
2. `pyproject.toml` declares `classification = "plugin"` (readable by packaging tools).
3. `manifest.json` declares capabilities, subjects, version.
4. Thin package re-exports `src/python/gatekeeper` (no forking of the ~2k LOC).
5. `make smoke` passes: imports gatekeeper through the plugin shell, asserts `classification=plugin`.
6. Existing gatekeeper tests still pass (dual-human / nats / phase2 / rate-limiting).
7. `docs/PACKAGES.md` extract-status line updated (skeleton exists; no image matrix).
8. Compound note `docs/solutions/asp-630-gatekeeper-skeleton.md`.

## 3. Layout

Mirrors the sibling `aspen-edge-rrm` docs-lite pattern, staying inside aspen-os:

```
plugins/aspen-gatekeeper/
├── pyproject.toml            # name aspen-gatekeeper, [tool.aspen] classification = "plugin"
├── manifest.json             # capabilities, subjects, version
├── aspen_gatekeeper/__init__.py   # thin re-export of gatekeeper (SoR stays src/python/gatekeeper)
├── tests/test_skeleton.py    # smoke: import + classification assert
├── Makefile                  # make smoke
├── README.md                 # one-pager
└── SECURITY.md               # one-pager
```

- SoR: `src/python/gatekeeper/` — untouched (no fork, no edits).
- Import path: `make smoke` puts both `plugins/aspen-gatekeeper` and monorepo
  `src/python` on `PYTHONPATH`; the shell package imports `gatekeeper` from the monorepo.

## 4. Out of scope / hard stops

- No new public GitHub repo; no `build-deb.sh` / ISO / production Dockerfile change.
- No live NATS restart, nkey rotate, money/publish/creds.
- No ASP-432/433/434/435/418/370 (G9 / host apply); Grok Build stays parked.
- No extract — `src/python/gatekeeper/` remains monorepo SoR (extract is a later packaging-sprint + Captain-signoff step).

## 5. Implementation steps

1. Write `pyproject.toml` with `[tool.aspen] classification = "plugin"`.
2. Write `manifest.json` (capabilities: safety-subject enforcement, credential-strip proxy, capability tokens, rate limits; subjects from nats_client).
3. Write thin `aspen_gatekeeper/__init__.py` (re-export gatekeeper `__all__`).
4. Write `Makefile` with `make smoke` (venv python, PYTHONPATH both dirs).
5. Write `tests/test_skeleton.py` (imports plugin shell + asserts classification via tomllib).
6. Verify: `make smoke` + run existing gatekeeper pytest files.
7. Update `docs/PACKAGES.md` extract-status line.
8. Compound note.
9. Commit; hand to Aider QA (`READY_FOR_AIDER_QA`, `in_review`).

# ASP-564: Gatekeeper Phase 2 — token lifecycle + credential strip (ADR-0009)

**Parent:** ASP-563 (Weekly Architecture Review) · **Linear:** BEL-215 residual
**Design source:** `docs/adr/ADR-0009-capability-based-gatekeepers.md` (accepted) +
Phase 1 delivery via ASP-540 (approval gate, dual-human, audit).

## Problem

Phase 1 (ASP-540) delivered proposal interception, the dual-human gate, and
durable audit, but left the remaining ADR-0009 requirements out of scope:

1. Capability tokens are granted but have **no lifecycle** (issue / consume /
   refresh / expire / cleanup) — a granted capability never expires.
2. Agents still need a **broad-credential-free path**: ADR-0009 §Hermes/Paperclip
   requires adapter config to route external calls through the gatekeeper and
   **no agent image holds broad credentials**.
3. No **immutable proxy enforcement** for safety-adjacent NATS subjects —
   enforcing only at proposal time leaves direct publish paths ungated.

Do not redesign Phase 1. Do not weaken the dual-human gate.

## Plan (Phase 2 DoD)

1. **Token lifecycle** — `TOKEN_REGISTRY` with `active → consumed | expired`
   states; short TTL issue (15 min), one-shot idempotent consume, refresh
   (+15 min, refuses consumed/expired), force-expire, stale-token cleanup.
   Every path audited (consume/refresh/expire + deny variants).
2. **Credential strip** — `GatekeeperProxy` / `NATSAgentProxy`: agents hold only
   an endpoint reference (no credentials), acquire a fresh token per action via
   `request_capability`, consume one-shot after execution. No credential fields
   on proxy instances.
3. **Immutable proxy enforcement** — `SafetySubjectEnforcer`: immutable pattern
   set (`tuple`), safety-adjacent subjects deny direct publishes without a valid
   active token; fail-closed on unknown/expired/consumed.
4. **Tests + compound note** — `tests/test_gatekeeper_phase2.py` covering all
   three capabilities + audit trail; `docs/solutions/asp-564-...` compound note.

## Success criteria

- Phase 2 behavior documented (solution doc) and all tests green.
- No regression in Phase 1 gatekeeper / sentinel suites.
- No broad credentials introduced; dual-human gate untouched.
- Final disposition: `in_review` + `READY_FOR_AIDER_QA` (never `done` by
  implementer).

## Out of scope

- Production token store (in-memory `TOKEN_REGISTRY`; Redis/PG later).
- Hermes/Paperclip image rebuilds and live provisioning — proxy path only.

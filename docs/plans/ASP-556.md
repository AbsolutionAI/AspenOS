### Root cause of the pytest failures

`tests/test_memory_promote.py` hardcodes `timestamp="2026-08-06T00:00:00Z"` in its
scoring fixtures. Today is 2026-09-05, exactly 30 days later. `memory_promote._is_recent()`
uses a 30-day recency window (`_RECENT_WINDOW_DAYS = 30`); anything older gets
`score *= 0.6`. The fixtures are now *just barely* outside the window:

| Test | Expected | Actual | Why |
|------|----------|--------|-----|
| `test_decision_scores_high` | 0.95 | 0.57 | 0.95 → ×0.6 decay |
| `test_cross_referenced_above_threshold` | ≥ 0.7 | 0.51 | 0.85 → ×0.6 decay |
| `test_promote_returns_memory_id` | memory id | None | score 0.57 < 0.7 threshold |
| `test_dry_run_...` | promoted types | no facts.jsonl | nothing promoted |

This is a **time-bomb test bug**, not a product regression. The scoring module is
correct; the fixed test fixtures have aged past the recency window.

## Fix plan

**File touched:** `tests/test_memory_promote.py` (test-only change, no product code)

- Add a module-level helper `recent_ts()` that returns a timestamp ~1 day in the
  past relative to `datetime.now(timezone.utc)`, always inside the 30-day window.
- Replace the hardcoded `2026-08-06T00:00:00Z` "recent" timestamps (scoring,
  promotion, dry-run, human-authored tests) with `recent_ts()`.
- Keep `2025-01-01T00:00:00Z` in `test_old_entries_decay` — that test deliberately
  exercises the decay path and must use a genuinely old timestamp.
- Optionally use a time travel / monkeypatched `_now` for exactness instead.

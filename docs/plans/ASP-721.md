# ASP-721 — port the ci-assertion-hardening nats-server install guard — plan

**Base:** `origin/master` @ `101a778`

## Problem

`origin/fix/ci-assertion-hardening` (`236f7b1`) was flagged as safe to delete in ASP-694, then
re-verified as **stale, not superseded**: it holds one piece of content that never reached
master. The branch is parked because cherry-picking it would silently delete three CI jobs and
a dozen `scripts/smoke-test.sh` checks — its base predates them.

What master is actually missing:

```sh
git show origin/master:.github/workflows/ci.yml | grep -n 'set -euo pipefail\|command -v nats-server'
# no matches
```

## Approach — port by hand, do not cherry-pick

Take exactly two things from `236f7b1` onto current `master`, inside the existing `smoke` job
install step:

1. `set -euo pipefail` as the first line of the `Smoke` step — the part with teeth. GitHub
   Actions runs steps under `bash -e` only; `pipefail` is what makes `curl … | tar xz` fail on
   the `curl` half, and `-u` turns an unset variable in that multi-line step into a hard
   failure.
2. An idempotency guard around the download + `sudo cp`:
   `if ! command -v nats-server …; then … fi`, closing with `command -v nats-server` so the
   step fails loudly if the install did not land on `PATH`.

Plus the contract test that keeps both strings from being edited away:

3. `tests/test_ci_assertions.py::test_ci_nats_install_is_guarded`, scoped to the `smoke` job
   block rather than the whole file (a bare file-wide `in` check passes for any job).

### Deliberately not ported

- **nats-server stays `v2.14.5`.** The stale branch pins `v2.14.3`. No downgrade.
- **No cherry-pick of `236f7b1`.** Its base predates `security-devonly-isolation`,
  `verify-package-signature`, `security-model-digests` and ~12 later smoke checks; it also
  deletes 12 of the 15 tests in `test_ci_assertions.py`.
- Nothing else: no `scripts/smoke-test.sh` edit, no other workflow, no job added or removed.

## Out of scope

- Deleting `origin/fix/ci-assertion-hardening` — that is a post-merge action once this lands.
- Merging any open PR; CE gates own that.
- ASP-730 (`python-test-suite` job) already exists on PR #60 — not re-implemented here. The
  two edits are in different regions of `ci.yml` (interior of `smoke` vs a new job), so they
  merge independently.

## Risk

Low. The guard is idempotency, not a behaviour change: on a clean runner the block runs
exactly what runs today, at the pinned `v2.14.5`. The only behavioural delta is `pipefail`
making a partial `curl | tar xz` failure fatal — which is the point of the ticket.

# Plan: ASP-478 — Forward-port C11 sandbox allowlist fix (6 missing syscalls on kernel 7.x)

## Problem
On kernel 7.x, glibc init and runtime call 6 syscalls that are missing from `sandbox_run.c`'s seccomp allowlist:
`sigaltstack`, `prctl`, `poll`, `sched_getaffinity`, `get_mempolicy`, `landlock_create_ruleset`.

Without these, C11 sandboxed processes are killed by seccomp before they can start, causing `make smoke` C11 tests to fail.

Found by ASP-477 nightly check (2026-08-25). The fix exists on `hermes/asp-459-packaging-forward-port` but was never forward-ported to `master`.

## Approach
1. Verify the fix commit on `hermes/asp-478-c11-kernel7-allowlist` (already created by previous work).
2. Cherry-pick `f2f68fb` onto `master`.
3. Build and verify with `make sandbox test` and `make smoke`.
4. Push to `origin/master`.

## Files
- `src/c/sandbox_spike/sandbox_run.c` (only file changed)

## Changes
- Add `SCMP_SYS(sigaltstack)`, `SCMP_SYS(prctl)`, `SCMP_SYS(poll)`, `SCMP_SYS(sched_getaffinity)`, `SCMP_SYS(get_mempolicy)`, `SCMP_SYS(landlock_create_ruleset)` to the seccomp allowlist.
- Add `ns_warn()` helper function for EPERM on namespace unshare operations.
- Remove unused `ns_flags` variable (suppresses compiler warning on unused return).
- Rename trace log field from `ns` to `ns_req` for clarity (it logs requested flags, not actual namespace bits).

## Non-goals
- No new syscalls beyond the 6 identified by ASP-477.
- No architectural changes to the sandbox or seccomp mechanism.

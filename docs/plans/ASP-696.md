# ASP-696: Delete HybridIntel stub and reconcile `osint-threat` skill

Implements the architect's decision in [ASP-695](/ASP/issues/ASP-695): **delete as dead
code**. No OSINT engine, no `/api/intel` route, no replacement.

## Problem

`src/python/services/hybrid_intel.py` is a 30-line self-labelled stub (`sweep()` is
`pass`, `get_status()` returns `{"enabled": False}`, `generate_brief()` returns
`"Intel engine not fully configured"`, `IntelItem.to_dict()` returns `{}`, and it
logs `"HybridIntel initialized (stub)"`). It has **zero importers**. The only
reference in the whole tree is prose in
`src/python/lib/skills/osint-threat/SKILL.md`.

That prose names a second, also-nonexistent service (`osint_sensor`), and
`src/python/lib/dashboard/intel.html` is a 17 KB dashboard page that calls six
`/api/intel/*` endpoints that have **no handler anywhere in the tree**.

So the repo currently ships two dead stubs plus a dashboard page bound to a
nonexistent API, and a skill that advertises both. Four sweeps (2026-09-16, -18,
-19, -29) deferred the cleanup. [ASP-695](/ASP/issues/ASP-695) made the call;
this ticket executes it.

The real OSINT contract is ADR-0007 subject `aspen.sentinel.osint.ingest`
(publish-only diode). A second aggregation engine in `services/` would fork it.

## Discovery (verified this run)

Repo-wide `rg` at `HEAD` (`cba7f7a`):

| Symbol | Live references | Verdict |
| --- | --- | --- |
| `hybrid_intel` | 1 — `osint-threat/SKILL.md:9` prose only | safe to delete |
| `HybridIntel` | 1 — the file's own `class` + log line | safe to delete |
| `osint_sensor` | 2 — both in `SKILL.md` prose | never existed; remove |
| `/api/intel` | 7 — all inside `intel.html` itself | no handler exists |
| `intel.html` | **0** — no route, no nav link, no build ref | safe to delete |

Why `intel.html` is provably dead:

- `dashboard/server.py:42` sets `STATIC_DIR = _HERE / "static"`, and
  `_serve_static_file()` only resolves inside that directory. `intel.html` sits
  beside `server.py`, not inside `static/`, so it is not servable.
- It is absent from the top-level `dashboard/` tree, so it is not a vendored
  sibling of `index.html` / `marketplace.html` either.
- Neither `dashboard/index.html` nor `src/python/lib/dashboard/index.html`
  contains an `intel` nav link.
- Nothing in `tests/`, `packaging/`, or `scripts/` enumerates it.

## Solution

### 1. Delete `src/python/services/hybrid_intel.py`

`src/python/services/__init__.py` is empty (0 bytes), so no package export needs
pruning. No test, script, packaging manifest, or systemd unit references it.

### 2. Delete `src/python/lib/dashboard/intel.html`

Guarded on the discovery table above: it is unreferenced, and its only outbound
calls are six `/api/intel/*` fetches with no handler. Per the ticket: do **not**
invent the API to keep the page alive. The `HybridIntel` stub was never that API —
its `sweep()` was `pass`, so the page would have rendered six empty states anyway.

### 3. Reconcile `src/python/lib/skills/osint-threat/SKILL.md`

The skill stays registered (`agents/proxy.yaml:28`, `src/python/lib/proxy.yaml:27`,
`README.md:130`) and is **not** removed. Only the prose changes:

- Drop `- Integrate with hybrid_intel and osint_sensor services` (capabilities).
- Drop `- osint_sensor service` (dependencies).
- Keep `web_search / http tools`.
- Reframe LanceDB as optional agent memory backed by the existing
  `services/memory.py` (which already has a flat-file fallback when `lancedb` is
  not installed), **not** as an intel engine.
- Add a short **"Not this skill"** note: there is no `hybrid_intel` and no
  `osint_sensor` service; do not invent one. If fleet ingest is ever wanted, the
  subject is `aspen.sentinel.osint.ingest` (ADR-0007), and this skill does not
  publish it.

In-scope adjacent fix found during discovery, same file, same class of defect
("prose naming something that does not exist"): the capabilities line
`Store findings as DECISION / SEMANTIC memories` names a `DECISION` memory type
that does not exist. `services/memory.py:26-35` defines ten types —
`working`, `semantic`, `episodic`, `procedural`, `retrieval`, `parametric`,
`prospective`, `temporal`, `knowledge_graph`, `preference`. Corrected to real
types so the line is truthful.

### 4. Leave unchanged (explicit)

- `docs/sweep-results-2026-09-{16,18,19,29}.md` — historical record.
- `agents/proxy.yaml`, `src/python/lib/proxy.yaml`, `README.md` skill list.
- `docs/adr/ADR-0007-nats-subject-contracts-sentinel-c2.md`.
- `docs/solutions/asp-368-data-diode-recipe.md`.
- `docs/architecture/OSINT_INTEGRATION_MASTER_PLAN.md` — no `hybrid_intel` /
  `osint_sensor` references; not a stub, out of scope.
- ASP-651 / WorldMonitor / diode config.

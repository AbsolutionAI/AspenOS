# ASP-691: Make the Hermes holographic cross-check in `test_holographic_ingest.py` skip portably

## Problem

The 2026-09-29 nightly run of `scripts/check-nightly.sh` reported **148/150, 2 failures** against a
baseline of 1 known failure. The second failure is a new regression in section 13
(`no pytest failures`):

```
FAILED tests/test_holographic_ingest.py::test_explicit_db_env_writes_holographic
E   ModuleNotFoundError: No module named 'ruamel'
$PY -m pytest tests/ -v --tb=no
  -> 1 failed, 466 passed, 3 skipped
```

`tests/test_holographic_ingest.py:39-45` imports the **host-local, out-of-repo** Hermes agent tree
and guards the import with a two-name substring check:

```python
sys.path.insert(0, "/home/tech/.hermes/hermes-agent")
try:
    from plugins.memory.holographic.store import MemoryStore
except ModuleNotFoundError as exc:
    if "tools.registry" in str(exc) or "holographic" in str(exc):
        pytest.skip("Hermes holographic plugin not available", allow_module_level=False)
    raise
```

Two defects, both of which turn an *optional* external integration into a *suite* failure:

1. **Hardcoded host path.** `/home/tech/.hermes/hermes-agent` is this operator's absolute home
   directory. On any host that does not have that exact tree, the import raises
   `ModuleNotFoundError: No module named 'plugins'` — a message containing neither `tools.registry`
   nor `holographic`, so the guard re-raises and **the test fails**. The test as written can only
   pass on the machine it was authored on.
2. **Too-narrow guard.** The guard enumerates the two missing-module names observed when the Hermes
   tree was *absent*. Any other missing optional dependency inside the present tree escapes as a
   failure. On this host the tree exists, but its own dependency `ruamel` is not installed, so the
   guard re-raises on `No module named 'ruamel'`.

The repo-local assertion the test actually owns — `assert path.exists()`, that the dual-write
produced the ingest record — passes regardless. The `MemoryStore.search_facts` read-back is a
bonus cross-check against code the repo does not contain and cannot fix. ASP-541 (`ccf75ab`)
established graceful-skip-for-optional-deps as the repo idiom; this test is an incomplete instance
of that idiom, and the fix completes it rather than introducing a new pattern.

## Success criteria

- `python3 -m pytest tests/ -v` on this host reports **0 failures**, with the Hermes read-back
  skipped as an unavailable optional integration.
- The behaviour is host-independent: the suite skips cleanly both when the Hermes tree is absent
  and when the tree is present but has unmet optional dependencies.
- `scripts/check-nightly.sh` section 13 returns to passing, and the run drops back to the single
  known C11 p50 failure — i.e. the nightly verdict returns to the baseline of 1 failure.
- No change to `scripts/check-nightly.sh`, the runbook, or any product/runtime code. The change is
  confined to the test's optional-integration import guard.
- No new hardcoded absolute paths.

## Design

Treat the Hermes holographic store as what it is: an **out-of-repo optional integration**. Resolve
its location from an environment override with the current host path as a default, add it to
`sys.path` only when it is actually a directory, and skip on *any* `ModuleNotFoundError` raised
while importing it — including the dependency errors the old guard never anticipated.

```python
HERMES_AGENT_DIR = os.environ.get("HERMES_AGENT_DIR", "/home/tech/.hermes/hermes-agent")
if Path(HERMES_AGENT_DIR).is_dir():
    sys.path.insert(0, HERMES_AGENT_DIR)
try:
    from plugins.memory.holographic.store import MemoryStore
except ModuleNotFoundError as exc:  # optional, out-of-repo integration
    pytest.skip(f"Hermes holographic store unavailable: {exc}")
```

The override is `HERMES_AGENT_ROOT`, **not** a new `HERMES_AGENT_DIR`: `scripts/holographic_ingest.py:16`
already reads `HERMES_AGENT_ROOT` with the same default for the module this test exercises. Reusing
that name keeps one knob for one host path instead of two that can disagree.

Skipping on any `ModuleNotFoundError` is safe *because* the import target is entirely outside the
repository: no in-repo defect can hide behind it, and the in-repo assertion (`path.exists()`) runs
before the import and is unaffected.

An explicit `HERMES_AGENT_ROOT` override lets a host with the Hermes tree elsewhere run the
cross-check for real instead of skipping it, which is how this host gets genuine coverage back once
`ruamel` is installed.

## Non-goals

- Installing `ruamel`, or otherwise mutating the host environment to turn a skip into a pass. The
  nightly verdict must reflect the repo, not host package state.
- Changing the C11 p50 outcome. It is the documented hardware-dependent deviation
  (`make bench`: `c11_internal p50 = 3.672 ms` vs the ADR 0001 `< 2 ms` criterion).
- Refreshing the baseline's Python test counts. The observed totals have drifted from the baseline
  row; that is recorded as a deviation for the Architect, not silently rewritten here.

# ASP-374: H-010 — Install AppArmor profiles in deb postinst

**Mode:** IMPLEMENTATION. Stage AppArmor profiles into the Debian package and
load via `apparmor_parser -r` in `debian/DEBIAN/postinst` on the **installed
target** only.

Threat model reference: H-014 (6.5, AV:L/AC:M). Verified gap in ASP-575:
profiles exist in `security/apparmor/` but no deployment target installs them.

## Scope

- **build-deb.sh:** create `etc/apparmor.d/` in pkgroot and copy profiles in.
- **debian/DEBIAN/postinst:** add AppArmor section; `apparmor_parser -r` each
  profile (reload mode — NO `aa-enforce` here; firstboot is responsible for
  enforce).
- **Tests:** proof that profiles would be staged in the built .deb.
- **Nightly/CI:** add a check section that confirms profiles ship in the .deb.
- Do **not** `aa-enforce` on this live host.
- Do **not** sudo apply here.

## Changes

### 1. `scripts/build-deb.sh`

- Add `mkdir -p "$PKG_ROOT/etc/apparmor.d"` in the assembly section.
- Add copy loop for `security/apparmor/*` -> `$PKG_ROOT/etc/apparmor.d/`.
- Add `etc/apparmor.d/agnetic-agent` and `etc/apparmor.d/nats` to the layout
  validation list (or at minimum one profile to prove the dir ships).
- Set `chmod 644` on profiles.

### 2. `debian/DEBIAN/postinst`

- New section (before GPU detection, as section 6):
  - Check `command -v apparmor_parser` — skip gracefully if absent.
  - For each profile in `/etc/apparmor.d/` (`agnetic-agent`, `nats`, `ollama`):
    `apparmor_parser -r "$profile"` (replaces kernel cache, idempotent).
  - No `aa-enforce`. No fail if apparmor_parser absent (profile file still
    lands in `/etc/apparmor.d/` ready for firstboot).

### 3. Tests

- `tests/test_ci_assertions.py`: add test `test_build_deb_stages_apparmor` that
  greps `build-deb.sh` for the copy section.

### 4. `scripts/check-nightly.sh`

- New Section 17 (after Dev-only isolation): checks that profiles exist in
  `security/apparmor/`, that `build-deb.sh` mentions `etc/apparmor.d`, and that
  `postinst` contains the `apparmor_parser` call.

### 5. `docs/solutions/asp-374-apparmor-deb-postinst.md`

- Compound document recording what was done.

# ASP-724 — `test_holographic_ingest.search_facts` drift — plan

**Ticket:** [ASP-724](/ASP/issues/ASP-724) (backlog, low, unassigned — picked up by the ASP-742 daily sweep)

## Problem

`tests/test_holographic_ingest.py::test_explicit_db_env_writes_holographic` asserts the
dual-write by calling `MemoryStore.search_facts(...)`. That method does not exist in the
current Hermes holographic store, so the test fails with `AttributeError` on every host that
can import the plugin.

The drift is **latent on this host only by luck**. The test imports the plugin through a
`try/except ImportError` → `pytest.skip` guard, and this host has no `ruamel`, so the import
fails first and the `AttributeError` is never reached:

```
$ python3 -m pytest tests/test_holographic_ingest.py -q
.s...                                                    [100%] 4 passed, 1 skipped

$ python3 -c "import sys; sys.path.insert(0,'/home/tech/.hermes/hermes-agent'); \
    from plugins.memory.holographic.store import MemoryStore; print(hasattr(MemoryStore,'search_facts'))"
ImportError: No module named 'ruamel'
```

Install `ruamel` and the same worktree goes red. That is the ASP-706 incident class that
[ASP-730](/ASP/issues/ASP-730) and [ASP-733](/ASP/issues/ASP-733) are about: the suite's
red/green does not mean what the board reads it to mean.

## Discovery (verified this run, `HEAD` = `101a778`)

| Fact | Value |
| --- | --- |
| Writer | `scripts/holographic_ingest.py:117` — `store.add_fact(fact, category=category, tags=tags)` |
| Reader used by the test | `store.search_facts("OpenCode holographic")` — **absent** |
| Public read API that exists | `store.list_facts(category=None, min_trust=0.0, limit=50)` → `list[dict]` with `content` / `category` / `tags` |
| Other absent methods named in the ticket | `add`/`update`/`remove` are all `add_fact`/`update_fact`/`remove_fact` |
| Lifecycle helpers | `__enter__` / `__exit__` / `close()` all present |

## Decision: call the method that exists now

The ticket allows either *"call the method that exists now"* or *"skip only when the method is
absent, and say which"*. **We call the method that exists.**

Skipping when `search_facts` is absent is the wrong branch: it would keep the assertion dark
on exactly the hosts that can run it, and the dual-write is the DoD this test exists to prove.
A rename-aware skip is the same "skip to go green" shape the ticket explicitly rejects.

## Do

1. `tests/test_holographic_ingest.py` — replace `search_facts` with `list_facts()`, inside the
   store's own context manager, and assert on facts this ingest actually wrote:
   - `content` carries the source id `ASP-HOLO-1` (proves *this* record, not some other row),
   - `category == "decision"` (proves `_category()` routing survived the round trip).
   Both keys are chosen so the assertion does **not** re-implement `_compose_fact` and stay
   green if the formatter drifts.
2. `tests/test_holographic_ingest.py:39` — insert `hi._HERMES_AGENT` instead of the literal
   `/home/tech/.hermes/hermes-agent`. The writer resolves its root from that same module
   constant (`holographic_ingest.py:16-18`, env-overridable), so hardcoding a second copy in
   the test is what makes read-back and write target different trees on a host that sets
   `HERMES_AGENT_ROOT`. One line; the de-hardcoding sweep itself stays ASP-733's.

## Not in scope

- No change to `scripts/holographic_ingest.py`. The writer is correct; only the reader drifted.
- No de-hardcoding of the other `/home/tech` sites — [ASP-733](/ASP/issues/ASP-733), already
  implemented on PR #61 and awaiting its own QA gate.
- No `search_facts` shim added to the Hermes tree. That tree is an out-of-repo dependency;
  patching it would hide the drift instead of fixing the test, and it is not ours to change.
- No CI-job change ([ASP-730](/ASP/issues/ASP-730), Auditor-owned).

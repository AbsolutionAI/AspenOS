# ASP-781 — Catalog MemoryStore loader for holographic read-back

## Problem

Both `scripts/holographic_ingest.py` and `tests/test_holographic_ingest.py` load MemoryStore through one function in the ingest module. That function resolves the Hermes catalog install. It does not import `plugins.memory.holographic.store`. It does not search `installs/*/plugin-sources/holographic-*`. It does not restore files into Hermes core.

## Resolver

Add `catalog_plugin_dir()` and `load_memory_store()` to `scripts/holographic_ingest.py`. The test imports those. It does not grow a second path.

Search order, first directory that contains `store.py`, `holographic.py`, and `text.py`:

1. `ASPEN_HOLOGRAPHIC_PLUGIN` if set (tests and overrides only).
2. `$HERMES_HOME/plugins/holographic` when `HERMES_HOME` is set. This is Hermes `_plugins_dir()`.
3. `$HOME/.hermes/plugins/holographic`, but if HOME starts with `/home/tech/.hermes/`, use `/home/tech` instead. Do not call `expanduser("~")`. Under the aspen profile that remaps onto a profile home that is not the default catalog root.

Reject, even if an env var points there:

- any path containing `/plugin-sources/holographic-`
- any path containing `/plugins/memory/holographic` (the empty core tree)

If nothing qualifies, raise `ImportError` whose message contains "holographic read-back NOT verified".

Cache the loaded module by resolved directory. A later call for a different directory must not reuse the first module.

## Loader

- Insert `HERMES_AGENT_ROOT` (default `/home/tech/.hermes/hermes-agent`) on `sys.path` only so `hermes_state_wal` resolves. Do not import `plugins.*` from that tree.
- Register an empty package module (name `aspen_holographic_catalog`, or a path-hash suffix when the directory changes) with `__path__` set to the catalog directory. Do not execute the plugin `__init__.py`.
- Load `store.py` with `importlib` under that package so `"from . import holographic"` and `"from .text import ..."` resolve.
- Return that module's `MemoryStore`.

`write_holographic` calls `load_memory_store()`. Failure isolation stays: never raise to the ingest caller. If the catalog directory is absent, stderr must include "holographic read-back NOT verified" and the function returns `None`. Any other exception still returns `None`, but it must not use that NOT-verified phrase (that phrase means the plugin was absent, not that a write was checked).

## Test

`test_explicit_db_env_writes_holographic` deletes its own `sys.path.insert` of the Hermes core tree and its direct `plugins.memory.holographic.store` import.

- Call `hi.load_memory_store()`.
- `ImportError` whose text contains "read-back NOT verified": `pytest.skip` with that same text. This skip is not a pass. Do not comment a skipped run as green.
- Any other exception, including `ModuleNotFoundError`: `hermes_state_wal` after the catalog directory was found: fail. A present plugin with a broken library path is a defect, not an optional skip.
- On success, keep the existing assertion: `MemoryStore(db_path=str(db)).list_facts()` and `ASP-HOLO-1` in some content. Do not call `search_facts`.

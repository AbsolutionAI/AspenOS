# ASP-538: Integration test for estop dual-human clear gate

## Summary

Add integration test coverage for the estop dual-human clear gate per
ADR-0003 §Safety and H-007 (CVSS 9.0).

## Current state

- `EdgeRRM` subscribes to `aspen.safety.estop` and `aspen.safety.clear`
- `_on_clear` unlatches estop unconditionally — **no dual-human gate**
- `aspen.safety.authorize_clear` subject is **not subscribed to**
- No test validates that `clear` requires two distinct humans

## Changes

### 1. EdgeRRM implementation (`aspen_edge/rrm.py`)

- Add `_clear_auths: set[str]` field to track distinct human IDs
- Subscribe to `aspen.safety.authorize_clear` in `start()`
- `_on_authorize_clear(env)`: extract `human_id` from envelope data, add to
  `_clear_auths`, emit audit event
- `_on_clear(env)`: check `len(_clear_auths) >= 2` before unlatching; if
  insufficient, emit audit event `clear_refused_insufficient_auths` and leave
  estop latched
- Add `CLEAR_AUTH_WINDOW_SECONDS = 300` (5-minute window for authorize_clear);
  prune stale authorizations on each `_on_authorize_clear` / `_on_clear` call

### 2. Integration test (`tests/test_rrm.py`)

Add `TestEstopDualHumanClear` class with:

| Test | Assertion |
|------|-----------|
| `test_clear_alone_never_unlatches` | `clear` with zero `authorize_clear` → estop stays True |
| `test_single_auth_never_unlatches` | 1 `authorize_clear` + `clear` → estop stays True |
| `test_dual_auth_then_clear_unlatches` | 2 distinct `authorize_clear` + `clear` → estop becomes False |
| `test_same_human_twice_equals_one` | Same `human_id` twice + `clear` → estop stays True |
| `test_audit_records_refused_clear` | Verify `clear_refused_insufficient_auths` appears in audit log |

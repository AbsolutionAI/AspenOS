# ASP-726 — `test_explicit_db_env_writes_holographic` asserts a method that does not exist

## Problem

`origin/master` is green. It is green **by accident**.

`tests/test_holographic_ingest.py:53` calls a method the Hermes holographic store does not
have:

```python
store = MemoryStore(db_path=str(db))
hits = store.search_facts("OpenCode holographic")   # AttributeError
assert hits, hits
```

`MemoryStore` (`/home/tech/.hermes/hermes-agent/plugins/memory/holographic/store.py`)
exposes `add_fact`, `update_fact`, `remove_fact`, `list_facts`, `record_feedback`,
`release_all_under`, `close`. There is no `search_facts`. `grep -rn search_facts` over the
entire Hermes tree returns nothing — the method was never written.

The line only *looks* safe because on this host the import above it raises
`ModuleNotFoundError: No module named 'ruamel'` (pulled in by `hermes_yaml.py:10`), and
`445f806` made that skip. **The skip runs first, so the `AttributeError` never executes.**

Two independent host states, both verified on a clean `origin/master` worktree:

| Host state | Import | Result |
|---|---|---|
| no `ruamel` (this host, and every CI runner) | raises | **skip** — suite green |
| `ruamel` present (the documented Hermes install) | succeeds | **AttributeError — suite red** |

`ruamel.yaml==0.18.16` is a declared dependency of the Hermes tree for Python ≥ 3.14
(`pyproject.toml:56`). This repo runs 3.14.4. So the configuration Hermes documents as
supported is the one that breaks this suite.

### The second defect: the assertion could not have passed either

Even with a working search, the needle is wrong. `_compose_fact` prefixes the body with a
provenance header, so the stored content is:

```
[opencode/ASP-HOLO-1 agent=opencode project=aspen-os] Decision: dual-write OpenCode ingest into holographic.
```

`"OpenCode holographic"` is **not a substring** of that. The words are separated by
`ingest into`. Any substring search on the original needle returns zero hits, and
`assert hits` fails. The test has never been capable of passing on a correctly-provisioned
host — it was green only because it never ran.

The assertion has therefore provided **zero** coverage of the one thing it names: that
OpenCode ingest actually dual-writes into the holographic store.

## Why `445f806` did not catch it, and was not wrong to land

`445f806` fixed a real bug — the module-name allowlist failed on hosts without `ruamel`.
Broadening the guard to `ImportError` was correct for *that* bug. But a skip guard can only
prove the import path is sound. It cannot prove the code *behind* the import ever runs, and
here it has been hiding an `AttributeError` on the other side. The guard made the failure
silent rather than absent.

This is the same shape as the `test_memory_mcp.py` CE-GATE on [ASP-709](/ASP/issues/ASP-709):
a guard widened to `except ImportError` in front of **in-repo** code removes coverage that
was load-bearing. There the module is in-repo (`mcp/aspen-memory-mcp/src`). Here the module
is genuinely out-of-repo — but the *call* into it is ours, and a call we have never executed.

## Scope

The assertion, and the guard that hides it. Nothing else.

Out of scope: `scripts/holographic_ingest.py` (the swallowed-exception behaviour in
production is pre-existing), installing `ruamel`, vendoring Hermes, adding `tests/` to CI.

## Change

`tests/test_holographic_ingest.py`:

1. **Assert the real API.** `MemoryStore.list_facts()` is the read path that exists. Match
   on `ASP-HOLO-1` — the `source_id`, which `_compose_fact` puts in the header verbatim and
   which is unique to this record. That makes the assertion a genuine round-trip check:
   write a record through `ingest_record`, read it back out of the holographic store by an
   identifier only that record carries.

2. **Keep the dual-write failure load-bearing.** Assert the store is non-empty *and* that
   the specific fact is present. A regression that stops writing to the holographic DB must
   fail, not skip.

3. **Make the skip honest about what it costs.** The skip reason should say the read-back
   did not run, so a green suite never reads as evidence the dual-write was verified.

## Not doing

* **Not** installing `ruamel` into the venv. A green host is not the fix; the assertion is.
* **Not** widening the guard further. `ImportError` is already the broadest correct signal.
* **Not** adding `tests/` wholesale to CI. Real gap, separate change, needs its own baseline.
* **Not** touching `tests/test_memory_mcp.py`. Its guard is correct for a genuinely optional
  PyPI package, and [ASP-709](/ASP/issues/ASP-709) already carries that discussion.

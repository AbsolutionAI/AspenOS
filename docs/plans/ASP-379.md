# ASP-379 — Plan: Tool-execution behavioral anomaly detection (H-015/F-015)

**Issue:** ASP-379 (LOW, F-015 / "H-015" label)
**Parent:** ASP-298 — Security Threat Model v2.2
**Status:** Implemented
**Date:** 2026-09-20

## 1. Problem

The fleet audits agent tool calls to the ADR-0007 sentinel audit journal
(`aspen.sentinel.audit.event` / JSONL, ASP-537) but nothing **looks at the
sequence of tool calls**. A compromised or misbehaving agent (RCE, poisoned
skill, red-team escape) shows up as a recognizable tool *pattern* — sensitive
read followed by egress, a burst of high-risk calls, repeated denials probing
the fence, an error storm — before a human would notice from raw events.

Spec acceptance (captain 2026-09-21):
- Detector over tool-audit events (window + simple stats or sequence rules).
- **Fail-open / log-only** — never blocks `propose_act`.
- Tests with fixture sequences (benign vs anomalous). No live cell.
- Compound `docs/solutions/asp-379-tool-anomaly.md`.

## 2. Design decisions

| Decision | Why |
|----------|-----|
| **Consume ADR-0007 dicts** (`actor`, `action`, `target`, `result`, `ts`, extra `tool`) | Same schema as `sentinel.audit` journal + JetStream; detector is source-agnostic over the audit stream |
| **Library in `src/python/sentinel/`** | Lives beside the audit publisher/consumer it analyses; tests follow the existing `sentinel.*` import pattern |
| **Four explicit rules** (R1 sequence + R2–R4 window stats) | Simple, auditable, fixture-testable; no ML/baseline warmup needed |
| **Fail-open contract** | Detector never raises, never blocks; every finding carries `fail_open: true` |
| **`scan(events)` batch + `feed(event)` incremental** | Usable by a batch CLI (journal replay) or a future live consumer without API change |
| **CLI `scripts/tool-anomaly.py`** | Mirrors `scripts/sentinel-audit.py` style; scans journal / stdin JSONL; optional `--emit` to re-audit findings |

## 3. Rules

| ID | Name | Rule (same actor) | Severity |
|----|------|-------------------|----------|
| R1 | `sensitive_read_then_egress` | sensitive read (`read_file`/`search_files`/`list_dir`/`kg_query`/`vault_list` on a sensitive target, or `sensitive` in target) → egress (`http_post`/`delegate_to_agent`/`shell` with net target) within window | high |
| R2 | `high_risk_burst` | ≥ `burst_high_risk_min` high-risk actions (`shell`, `http_post`, `http_get`, `write_file`, `delegate_to_agent`, `opencode`, `opendesign`, `policyexec`) within window | medium |
| R3 | `denial_probe` | ≥ `denial_min` of the same high-risk action with `result=deny` within window | medium |
| R4 | `error_storm` | ≥ `error_min` of the same tool with `result` in `failed/error` within window | low |

Window default 120s; `[]`/bare reads on normal targets are never flagged.

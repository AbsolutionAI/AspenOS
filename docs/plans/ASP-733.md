# ASP-733 — De-hardcode `/home/tech` so the tree runs on any host

**Plan author:** Opencode (daily implementation sweep, [ASP-734](/ASP/issues/ASP-734))
**Status:** plan written before product code, per `docs/COMPOUND_ENGINEERING.md` step 2.

## Problem

Nine call sites hardcode this repo's operator home directory. The code only works on the
machine it was written on, and the mechanism to override it already exists in two of the
three cases — it is just not used as the default.

| File | Hardcoded | Env override that exists |
|---|---|---|
| `scripts/memory_ingest.py:40` | `/home/tech/.aspen/memory/ingest` | `AGNETIC_MEMORY_INGEST_DIR` |
| `scripts/memory_promote.py:50` | `/home/tech/.aspen/memory/ingest` | **none** |
| `scripts/memory_promote.py:51` | `/home/tech/.aspen/memory/facts` | **none** (only `--facts-log`) |
| `scripts/holographic_ingest.py:15` | `/home/tech/.aspen/memory/holographic.db` | `ASPEN_HOLOGRAPHIC_DB` (used at write time) |
| `scripts/holographic_ingest.py:17` | `/home/tech/.hermes/hermes-agent` | `HERMES_AGENT_ROOT` |
| `scripts/push-ci-workflows.py:10` | `cd /home/tech/agnetic-os && git remote …` | **none** |
| `services/scripts/start-all-agents.sh:12` | `PROJECT_ROOT="/home/tech/agnetic-os"` | **none** |
| `services/scripts/shared-store-init.sh:7` | `PROJECT_ROOT="/home/tech/agnetic-os"` | **none** |
| `tests/test_holographic_ingest.py:39` | `sys.path.insert(0, "/home/tech/.hermes/hermes-agent")` | `hi._HERMES_AGENT` is the real knob |

## Why it matters now

[ASP-730](/ASP/issues/ASP-730) added a required `python-test-suite` CI job and it failed on its
first run for exactly this reason:

```
tests/test_paperclip_memory_ingest.py::TestPaperclipMemoryCLI::test_cli_no_ingest_dir_uses_default
E   assert 2 == 0
paperclip-memory: ingest skipped: [Errno 13] Permission denied: '/home/tech'
```

That test is guarded by `if default.exists():` — it silently degrades to a no-op on a runner
that has no `/home/tech`, and only runs the real assertion on the author's machine. The suite
is green everywhere *because* the hardcoded path is absent, not because the code is portable.

## The finding that decides the design

`$HOME` **is** `/home/tech` on the current deployment target. `/home/tech/.aspen/memory/{ingest,facts}`
and `/home/tech/.hermes/hermes-agent` all exist on this host. So deriving from `Path.home()` is a
**strict generalization, not a migration**: the existing deployment resolves to byte-identical
paths, and every other host resolves to its own home. That satisfies acceptance criterion 3
("the packaged install still finds its data") for free.

There is exactly **one** caller where `$HOME` is not the operator's home, and investigating it
changed the plan rather than confirming it.

`systemd/agnetic-agent@.service` runs `agents/agent_daemon.py` with `User=agnetic`, and
`agent_daemon.py:54` defaults `ingest_dir=None`, which falls through to `DEFAULT_INGEST_DIR`.
The instinct is that a `$HOME` derivation relocates the store for that unit. It does not — that
store is **already unreachable today**, for a different and more interesting reason:

```
ProtectHome=true            # /home is entirely inaccessible to the unit
ReadWritePaths=/var/log/starship /var/log/agnetic /tmp
```

`/home/tech` is behind `ProtectHome=true` and is not in `ReadWritePaths`, so the hardcoded
`/home/tech/.aspen/memory/ingest` write raises `EACCES` on every command the agent processes.
`agent_daemon.py:84` swallows it at `log.debug`, so it is invisible in the journal at default
level. The packaged deployment has been silently dropping agent memory ingest, and this ticket's
hardcoded path is why nobody noticed: a `$HOME`-derived path fails the *same* way, so the change
is neutral — but it cannot be the fix either.

Picking the durable data root for the packaged unit (`/var/lib/starship` vs `/tmp/agnetic-data`
vs relaxing `ProtectHome`) interacts with `ProtectSystem=strict`, `ReadWritePaths`, `backup.sh`,
`restore.sh` and migrating the existing `/home/tech/.aspen` contents. That is an architecture
decision with a security dimension, so per the escalation rule this plan **does not invent it** —
the derivation ships neutral and the packaging decision is escalated to the Aspen Architect with
the evidence attached.

This is why the ticket's acceptance criterion 3 ("the packaged install still finds its data on
the existing deployment target") is satisfiable without a packaging change: `$HOME` *is*
`/home/tech` for every operator-shell caller, so all of `agents/*_memory.py` (which import in the
operator's own process), `scripts/memory_ingest.py` invoked directly, and
`scripts/memory_promote.py` (run by hand, no timer — verified: no `memory_promote` reference in
`systemd/`) resolve to byte-identical paths.


## Approach

### 1. One shared derivation module: `scripts/paths.py`

New module, single responsibility, no imports beyond stdlib:

```python
def data_home() -> Path      # $ASPEN_DATA_HOME  →  $XDG_DATA_HOME/starship  →  ~/.aspen
def hermes_agent_root() -> Path  # $HERMES_AGENT_ROOT  →  ~/.hermes/hermes-agent
def memory_ingest_dir() -> Path  # $AGNETIC_MEMORY_INGEST_DIR  →  data_home()/memory/ingest
def memory_facts_dir() -> Path    # $AGNETIC_MEMORY_FACTS_DIR  →  data_home()/memory/facts
def holographic_db() -> Path      # $ASPEN_HOLOGRAPHIC_DB      →  data_home()/memory/holographic.db
```

Precedence is **explicit env override → XDG → home**, matching the repo's existing convention
(`${XDG_CONFIG_HOME:-$HOME/...}` in `scripts/install-models.sh`, `detect-gpu.sh`,
`select-profile.sh`). Every function is re-evaluated on call, not cached at import, so tests can
move `$HOME` with `monkeypatch` — a module-level constant would bake in the first host that
imported it and make this class of bug untestable.

`ASPEN_DATA_HOME` is new and joins the existing `ASPEN_*` namespace (`ASPEN_HOLOGRAPHIC_DB`,
`ASPEN_NATS_URL`, `ASPEN_SENTINEL`, …). It is the one knob a deployment needs to pin the whole
Aspen data tree in a single place; the per-path vars stay for surgical overrides.

### 2. Import it from the three Python modules using the repo's existing dual-import dance

`scripts/memory_ingest.py:110-112` already solves this exact problem for `holographic_ingest`
(tested as top-level `memory_ingest` *and* as `scripts.memory_ingest`; there is no
`scripts/__init__.py`). `paths.py` follows the same established pattern rather than inventing a
new one:

```python
try:
    from paths import memory_ingest_dir
except ImportError:
    from scripts.paths import memory_ingest_dir
```

### 3. Shell installers: derive `PROJECT_ROOT` from the script's own location

`start-all-agents.sh` and `shared-store-init.sh` live *in the tree*, so the tree root is
derivable and guessing is unnecessary:

```bash
PROJECT_ROOT="${AGNETIC_ROOT:-$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)}"
```

`${BASH_SOURCE[0]}` requires bash; `shared-store-init.sh` currently has **no shebang** and is not
`sourced` by anything in-repo, so it gets one (`#!/usr/bin/env bash`) as part of the change.

This also fixes a latent bug found in `shared-store-init.sh` while editing it: the store variable
is declared `SHARED_STORE` but every use site below reads `$SHARE_STORE` (missing `D`), so all
six agent memory paths silently resolved to `/memory/proxy.json` etc. Flagged explicitly because
it is a behavior change beyond the literal-path fix.

### 4. `push-ci-workflows.py`: stop shelling into a hardcoded path for a token

`os.popen("cd /home/tech/agnetic-os && git remote get-url origin | sed …")` scrapes a token out of
a git remote URL by regex. Replace with `$GH_TOKEN` → `$GITHUB_TOKEN` → `gh auth token`, and fail
loudly with the three names when none is available. Silent-empty-token is the failure mode this
replaces.

### 5. Packaging: escalated, not guessed

No `systemd/` change ships in this commit. The packaged unit's durable data root is escalated to
the Aspen Architect as its own issue with this evidence attached, because the answer changes the
unit's `ProtectHome`/`ReadWritePaths` hardening and requires migrating existing
`/home/tech/.aspen` contents. `ASPEN_DATA_HOME` is the knob that makes that follow-up a
one-line `Environment=` change rather than another code edit.

### 6. Tests

New `tests/test_home_paths.py`:

- derivation under a relocated `$HOME` (monkeypatched to `tmp_path`) — the property the ticket
  asks for and nothing currently asserts
- `XDG_DATA_HOME` wins over home; `ASPEN_DATA_HOME` wins over both
- explicit per-path overrides still win over every derived default
- `unset HOME` falls back to the passwd entry instead of raising
- a **grep guard** asserting no functional source under `scripts/`, `services/scripts/`, `agents/`
  hardcodes `/home/tech` — the same "gate script + CI job" shape as
  `scripts/check-nats-tls-default.sh` from ASP-684, so this cannot regress silently
- tighten `tests/test_holographic_ingest.py:39` to use the derived `hi._HERMES_AGENT` instead of
  a second hardcoded literal
- un-guard `test_cli_no_ingest_dir_uses_default`: today it only asserts when `default.exists()`,
  which is why it never caught this on CI. With a derived default pointed at `tmp_path` the
  assertion runs everywhere.

## Out of scope

- **`scripts/smoke-fleet-bus.py:23-24`** (`/home/tech/repos/...`) — that is a *candidate search
  list* for sibling checkouts, and the function already tries several roots first. Left alone.
- **`scripts/test-iso-auto.sh:27-28`** — verbatim inside the `preseed` block that writes the
  autoinstall answers; substituting a variable there would change the ISO's baked-in answer.
- **`scripts/install-daemon.sh:244`** — already correct: it is an install-time `sed` rewriting
  the source literal to `/etc/starship/nats`. With the default now derived, that rewrite becomes a
  no-op on a host where the literal is absent, which is harmless (`|| true`).
- **`docs/ARCHITECTURE_COMPLETE.md:329`** — prose describing the facts path. Updating it is a
  separate docs pass, not a code change.

## Risks

| Risk | Mitigation |
|---|---|
| Packaged unit's data root is wrong either way | Not made worse: the hardcoded `/home/tech` path is already unreachable under `ProtectHome=true`, so ingest fails today too. Escalated to the Architect rather than guessed. `ASPEN_DATA_HOME` exists so the fix is one line. |
| Silent `EACCES` remains invisible | Out of scope to change `agent_daemon.py`'s `log.debug` swallow, but recorded in the escalation so it is fixed together with the data root — a data root that is right but still failing silently is the same bug. |
| `SHARED_STORE`/`SHARE_STORE` fix changes real paths | Six paths start resolving where they always intended to; called out in the handoff for QA to check explicitly |
| `src/python/lib/scripts/` is a stale mirror carrying the same token scrape | Left alone (10 of its 28 files already diverge from `scripts/`, so it is a drifted vendored copy, not a live path). Reported as a finding instead of silently widened scope. |
| Module-level constants becoming functions changes import sites | `DEFAULT_INGEST_DIR` / `DEFAULT_FACTS_LOG` / `DEFAULT_HOLOGRAPHIC_DB` / `HERMES_AGENT_ROOT` stay as module attributes so the 4 `agents/*_memory.py` importers and 2 test call sites keep working unchanged; call sites that must track the live environment use the `paths` functions |

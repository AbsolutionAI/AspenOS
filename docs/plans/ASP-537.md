# ASP-537: Wire `aspen.sentinel.audit.event` publisher (Hardening)

## Problem

H-015 (threat model v2.2 §4.1 / §8 P1#4, CR 4.2): there is **no forensic trail that
records agent actions**. The subject `aspen.sentinel.audit.event` is defined in
ADR-0007 and already guarded in the NATS accounts config (ASP-536), but nothing
publishes to it and there is no storage or query path. Every local audit record
today is either an ephemeral in-memory list (`AUDIT_LOG`) or a non-durable
buffered message in `NATSGateClient`.

## Success criteria (DoD)

- A publisher writes durable audit events to the JetStream subject
  `aspen.sentinel.audit.event`.
- Event schema matches ADR-0007: `{event_id, actor, action, target, result, ts}`.
- Events are always backed by an append-only **JSONL file** (local durable
  write-path) **and** mirrored into **JetStream** for replay when a broker is
  reachable.
- A simple tail/query path exists (CLI `tail` / `query` on the JSONL, plus a
  JetStream consumer read for replay verification).
- Gatekeeper agent actions (`minimal_shim.log_audit`) flow through the publisher
  so grant/deny/propose_act decisions produce the audit trail.
- Offline resilience: broker unreachable → events still land in JSONL and are
  replayed to JetStream on reconnect (idempotent).

## Solution

### 1. New package `src/python/sentinel/`

`src/python/sentinel/audit.py` — `AuditEventPublisher`:

- `record(actor, action, target=None, result="ok", *, event_id=None, ts=None,
  **extra) -> dict`
  - always generates/enforces `{event_id (uuid4 hex), actor, action, target,
    result, ts (UTC ISO-8601)}`; `extra` fields are preserved for extensibility
    (e.g. `request_id`, `capability`).
  - **JSONL write is unconditional** (append + flush + fsync), so a file write
    never depends on NATS availability.
  - **JetStream publish is best-effort** via `js.publish(subject, payload,
    stream=..., headers={"Nats-Msg-Id": event_id})`. JetStream-side dedup + a
    local `.marker` file make `replay_pending()` idempotent.
- Stream bootstrap `_ensure_stream()`: `add_stream(name="ASPEN_SENTINEL",
  subjects=["aspen.sentinel.>"], storage="file", duplicate_window=...)` — idempotent
  (already-exists / subject-overlap degrades gracefully to core publish).
- `replay_pending()`: publish JSONL events whose `event_id` is not yet marked,
  then persist the marker.
- `tail(n)`, `query(...)`: JSONL read paths (backend for the CLI).
- `js_last(n)`: page the JetStream stream tail (stream_info + get_msg) for
  replay verification.
- Lifecycle: lazy `connect()` (imports `nats` only inside methods so tests and
  offline use work without nats-py), `close()`.
- Env: `ASPEN_NATS_URL`, `ASPEN_AUDIT_LOG` (default
  `/var/lib/aspen/sentinel/audit.jsonl`), `ASPEN_AUDIT_STREAM` (default
  `ASPEN_SENTINEL`), `ASPEN_AUDIT_FLUSH`.

`src/python/sentinel/__init__.py` re-exports `AuditEventPublisher` + helpers.

### 2. CLI `scripts/sentinel-audit.py`

Subcommands:

- `emit --actor --action [--target --result --log] [--nats-url]` — record one
  event and print it as JSON (works fully offline).
- `tail [-n N] [--json] [--log]` — last N events from the JSONL (default 20).
- `query [--actor A --action X --target T --result R --since ISO --limit N]` —
  filtered read of the JSONL.
- `replay [--log] [--nats-url]` — idempotent JSONL → JetStream backfill.
- `js-last [-n N] [--nats-url]` — tail the JetStream stream (verifies durable
  mirror).
- `check [--log] [--nats-url]` — report stream + JSONL state.

No `nats` import at module load; broker-only subcommands import lazily.

### 3. Wire gatekeeper (`src/python/gatekeeper/minimal_shim.py`)

- Add `set_audit_publisher(publisher)` and a module-level `_audit_publisher`.
- `log_audit()` keeps the existing in-memory `AUDIT_LOG` + NATSGateClient path
  (back-compat with tests) and additionally fans each event into the sentinel
  publisher (`record_sync` so the JSONL write always happens; JS publish is
  fire-and-forget on a running loop).
- `run_daemon()` constructs/registers a real `AuditEventPublisher` from env.

# ASP-543: Nightly Packaging & Deployment Check — Iteration 6

## Problem

The nightly check (`scripts/check-nightly.sh`) runs clean: **80 passed, 1 failed**
(the known C11 p50 benchmark deviation). Three coverage gaps remain:

| # | Gap | Detail |
|---|-----|--------|
| 1 | Python test suite not automated | Python tests (19 test files, 152+ tests) are recorded manually in the results doc; no formal check-nightly.sh section runs them |
| 2 | ISO directory structure unchecked | `iso/` directory (autoinstall profiles, hooks, package lists) has no static inventory check; would silently degrade |
| 3 | Dashboard static assets unchecked | 9+ JS/CSS files in `dashboard/static/` are not inventoried; a missing asset breaks the C2 UI silently |

## Fixes

### 1. Python test suite — Section 13

**File:** `scripts/check-nightly.sh`
**Change:** Add Section 13 — Python test suite — that runs `python3 -m pytest tests/ -v --tb=no`
and parses the summary line for pass/fail/skip counts.
**Rationale:** The most recent ASP-541 commit added `pytest.skip()` / `pytest.importorskip()`
guards for optional dependencies. The test suite is now CI-safe. Automated execution
prevents silent regressions.

### 2. ISO structure check — Section 14

**File:** `scripts/check-nightly.sh`
**Change:** Add Section 14 — ISO build structure — with static checks for:
- `iso/autoinstall/` directory exists
- Expected profiles exist: `edge`, `server`, `ops` user-data files
- `iso/config/hooks/` directory exists with at least one `.chroot` hook
- `iso/config/package-lists/` exists

**Rationale:** The ISO build is SKIP by design in CI (needs root/nested virt), but the
source tree should be statically validated so a broken `iso/` structure is caught
before the next manual ISO build.

### 3. Dashboard static assets — Section 15

**File:** `scripts/check-nightly.sh`
**Change:** Add Section 15 — Dashboard static assets — checking all expected files
under `dashboard/static/` exist: `style.css`, `ui.js`, `dashboard.js`, `agents.js`,
`chat.js`, `panels.js`, `incidents.js`, `boot.js`.

**Rationale:** The C2 dashboard depends on these files. A missing JS file causes
silent UI failures. Static inventory catches accidental deletion or broken paths.

# Plan: ASP-693 — restore the dead F-014 signed-package CI gate + guard the class

Daily implementation sweep. Queue sweep found no open implementation-engineer
tickets, so this sweep takes the highest-priority actionable item it could
prove. Proven item: **the F-014 signed-package security gate does not run in
CI**, and the fix that closes it was already written and closed without ever
reaching `master`.

## Problem

### The gate is dead on `master`

`.github/workflows/ci.yml:28-41` — job `verify-package-signature`:

```yaml
- name: Install gnupg2 + pytest
  run: |
    sudo apt-get update -qq
    sudo apt-get install -y -qq gnupg2
    pip install pytest
- name: F-014 signed-package gate (unsigned/tampered fixtures must fail)
  run: python -m pytest tests/test_package_signatures.py -q
```

`tests/conftest.py:3` imports `yaml`. pytest loads `conftest.py` for every
module under `tests/`, so `tests/test_package_signatures.py` — whose own source
imports only `os`, `shutil`, `subprocess`, `pathlib`, `pytest` — dies during
collection before a single F-014 assertion executes.

Hermetic reproduction on this branch (`yaml` shadowed by a module that raises,
so no network or venv is needed):

```bash
mkdir -p "$SCRATCH/noyaml"
printf 'raise ImportError("No module named %s")\n' "'yaml'" > "$SCRATCH/noyaml/yaml.py"
PYTHONPATH="$SCRATCH/noyaml" python3 -m pytest tests/test_package_signatures.py -q
# ImportError while loading conftest '.../tests/conftest.py'
# tests/conftest.py:3: in <module>   import yaml
# exit=4
```

| Condition | Result |
|---|---|
| `yaml` importable (local) | exit 0, 9 tests collected |
| `yaml` not importable (CI) | **exit 4 — collection error, 0 tests run** |

The job installs `gnupg2`, so `gpg` is present on the runner and the
`pytestmark` skipif in `tests/test_package_signatures.py` does **not** fire —
the gate is meant to run there, and it does not. The sibling job
`security-model-digests` (`ci.yml:51`) already installs `pyyaml` for exactly
this reason, so the requirement is established in-repo.

Net effect: F-014 is a green checkmark in CI that verifies nothing. Unsigned and
tampered-package fixtures are not exercised.

### The fix exists, and it is stranded

[ASP-682](/ASP/issues/ASP-682) is closed **`done`** with a one-line fix in commit
`6ce85f7` (`pip install pytest` → `pip install pytest pyyaml`). That commit
lives only on `fix/ci-verify-package-signature-pyyaml`:

```bash
git merge-base --is-ancestor 6ce85f7 master   # -> NO
git show master:.github/workflows/ci.yml       # still `pip install pytest`
```

The issue was closed on the strength of the commit existing, not the commit
being on `master`. The `done` status and the tree disagree; the tree is what CI
runs.

## Solution

1. **Land the stranded fix.** `verify-package-signature` installs `pyyaml`,
   matching the sibling `security-model-digests` job.

2. **Guard the class, not the instance.** A CI job that runs `pytest` under
   `tests/` must install every third-party top-level module `tests/conftest.py`
   imports, derived at test time from `conftest.py` itself rather than
   hardcoded. When someone adds a conftest import later, the guard demands the
   matching `pip install` in the same PR — instead of the next `done` ticket
   discovering it from a red CI run.

## Success criteria

- `verify-package-signature` satisfies the conftest-dependency contract.
- The guard test fails on `master` before the `ci.yml` edit and passes after —
  the fix is proven by the guard, not by assertion.
- Whole `tests/` suite green; the F-014 gate's 9 tests are reachable.
- No gpg fixture, key, or threat-model content is touched.

## Implementation notes

The guard parses `.github/workflows/ci.yml` as text (no `yaml` dep needed to
read it — a regex per job block), maps each job to the `run:` lines that invoke
`python -m pytest tests/...`, and requires the union of the job's `pip install`
lines to cover the conftest's third-party imports. It reports the missing
distribution name in the assertion message so the fix is obvious from the
failure text.

`conftest.py`'s third-party set is computed with `ast` +
`sys.stdlib_module_names`, so it stays correct as conftest evolves.

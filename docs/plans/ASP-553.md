# ASP-553: Nightly Packaging & Deployment Check — GitHub Actions Workflow

## Problem

The nightly check scripts (`scripts/check-nightly.sh`) and runbook (`docs/ops/NIGHTLY_PACKAGING_DEPLOY_CHECK.md`) are complete, but there is **no automated GitHub Actions workflow** to trigger the check on a schedule. The nightly check must be run manually, creating a gap in automated regression detection for:

- Binary build failures (Go CLI, Rust agent, C11 components)
- Debian package integrity
- Systemd unit drift
- Shell syntax regressions
- Python test suite regressions
- ISO build structure drift
- Dashboard static asset deletions
- Windows packaging artifact drift

## Success criteria

1. `.github/workflows/nightly.yml` created with daily 02:00 UTC schedule (`0 2 * * *`)
2. Workflow runs `bash scripts/check-nightly.sh` with the same toolchain setup as `ci.yml` (Go 1.22, Python 3.12, Rust stable, libseccomp-dev)
3. `workflow_dispatch` trigger enabled for manual runs
4. Results visible in GitHub Actions workflow logs
5. Workflow clones sibling repos at pinned commits for fleet-bus smoke test (matching ci.yml)

## Implementation

### File: `.github/workflows/nightly.yml`

Modeled on the `smoke` job from `.github/workflows/ci.yml`:

- **Trigger:** `schedule` (cron `0 2 * * *`) + `workflow_dispatch`
- **Steps:**
  1. Checkout repo
  2. Setup Python 3.12, Go 1.22, Rust stable
  3. Install deps (libseccomp-dev, gcc, pkg-config, pip packages)
  4. Build Go CLI and C11 components (needed for smoke tests)
  5. Checkout pinned sibling repos for fleet-bus smoke
  6. Install nats-server v2.14.5 for accounts validation
  7. Run `bash scripts/check-nightly.sh`

## Out of scope

- Changes to `scripts/check-nightly.sh` content (already stable at 15 sections, ~101 checks)
- Changes to `docs/ops/NIGHTLY_PACKAGING_DEPLOY_CHECK.md` baseline doc
- ISO or deb build from source in CI (SKIP by design — Option B per ISO_BUILDER.md)
- Docker image build
- Performance benchmarks
- Integration tests against real NATS mesh

## Verification

After merge, the workflow should be visible at `.github/workflows/nightly.yml` and trigger:
- On schedule: daily at 02:00 UTC
- On demand: via GitHub Actions → `nightly.yml` → "Run workflow" button

The workflow run log should show the same pass/fail counts as running `bash scripts/check-nightly.sh` locally.

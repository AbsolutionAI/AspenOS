# ASP-512: Nightly Packaging & Deployment Check

## Problem
Aspen OS has no automated nightly check to catch packaging drift, broken build artifacts, stale systemd units, or missing deployment paths before they reach end users. Historical audits (ASP-10, ASP-187, ASP-477) were all manual one-offs that caught problems like C11 seccomp allowlist drift, stale systemd units, and broken symlinks — but only after they had already landed.

## Success Criteria
1. A scheduled GitHub Actions workflow runs every night at 02:00 UTC
2. The workflow executes a dedicated nightly check script that:
   - Builds all Go binaries (starshipctl, starshipctl build)
   - Builds Rust agent (staragent via cargo)
   - Builds C11 components (sandbox_spike, policyexec, starshipd, heald)
   - Builds a Debian package and validates its layout
   - Runs the 83-check smoke test suite
   - Validates all systemd unit files syntax
   - Validates all scripts for shell syntax
   - Reports pass/fail summary clearly
3. Results are visible in GitHub Actions UI
4. A reference ops document (`docs/ops/NIGHTLY_PACKAGING_DEPLOY_CHECK.md`) exists

## Out of scope
- ISO build (requires root, not feasible in CI containers without nested virtualization)
- Windows packaging (no CI build host available)
- Deployment to staging/production environments
- Alerting beyond GitHub Actions notifications
- Performance benchmarking

## Plan
1. Create `scripts/check-nightly.sh` — the main nightly check entrypoint
2. Create `.github/workflows/nightly.yml` — scheduled CI workflow
3. Create `docs/ops/NIGHTLY_PACKAGING_DEPLOY_CHECK.md` — ops reference
4. Compound: `docs/solutions/asp-512-nightly-check.md`

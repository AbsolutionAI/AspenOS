# ASP-433: H-023 Hardware estop watchdog (independent of agent software)

**Source:** ASP-433 · threat model v2.2 (F-009 ampliation / manufacturing cell safety)
**ADR:** ADR-0003 (fleet/edge safety) · ADR-0009 (capability gatekeepers)
**Related:** ASP-432 (H-022 vault — **done** `0da87ee`) · ASP-538 (estop dual-clear) · ASP-573 (H-007 clear tests) · ASP-418 (D1 physical — still QUEUED LAST)

## Problem

Software estop latch and gatekeeper dual-human path live inside agent-controlled processes. If the agent runtime or gatekeeper is compromised or dead, the cell may lack an **independent** watchdog that forces safe state without trusting agent software.

H-023 requires a hardware-independent (or hardware-backed) watchdog contract: heartbeat from the software path, fail-closed open-loop trip, durable audit, no dependency on LLM/agent loops.

## Success criteria

1. **Contract module** (new, preferred under `src/python/safety/` or `src/python/gatekeeper/`):
   - `EstopWatchdog` (or equivalent) with:
     - `tick(source, ts)` — software path heartbeat
     - `deadline_ms` configurable (default ≤ 500ms class for cell; tests may use shorter)
     - `tripped` state when heartbeat overdue **or** explicit `force_trip(reason)`
     - `clear` only via dual-authorize pattern compatible with existing estop dual-clear (do **not** single-clear)
     - Fail-closed: missing config / clock / backend → tripped
   - Backend interface `WatchdogBackend` with:
     - `SimBackend` (in-process, default for tests/CI)
     - `FilePulseBackend` or GPIO stub interface documented for future hardware (no live GPIO this ticket)
2. **Independence invariant (tested):** killing / stopping the “agent” side (simulated by ceasing `tick`) trips watchdog without any gatekeeper/agent call.
3. **Integration surface (optional thin wire):** gatekeeper or a small daemon hook documents where ticks would be emitted; **do not** require NATS up for unit tests.
4. **Tests** `tests/test_estop_watchdog.py`:
   - trip on missed heartbeat
   - no trip while ticks arrive
   - force_trip
   - clear refused with <2 distinct authorizers
   - clear accepted with 2 distinct authorizers after trip
   - fail-closed on backend error
   - restart: durable trip latch survives process re-instance when using file-backed state (tmp_path)
5. Existing gatekeeper suites stay green (152+).
6. Threat model v2.2 gains **H-023** row → Implemented (design/sim) with residual “live hardware wire = Aspen START”.
7. Plan + solution compound under `docs/solutions/asp-433-estop-watchdog.md`.
8. End with `**READY_FOR_AIDER_QA**` comment; never mark `done`.

## Implementation notes

- Prefer pure-stdlib + pathlib; no new cloud deps.
- Keep module importable without root services package clash (same pattern as `vault_gate.py` if loading root services).
- Audit events: `safety.watchdog.trip`, `safety.watchdog.clear`, `safety.watchdog.tick_miss`.
- Sim profile (`light-cell`) may run watchdog in observe-only mode **if** explicitly configured; default plant-range = enforce.

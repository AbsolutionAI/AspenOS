## Problem

Fleet updates ship `.deb` artifacts with **no cryptographic integrity check**.
`scripts/update.sh --url` downloads and `dpkg -i`'s a package over TLS, and a
CI release may publish an artifact that was never signed. An attacker who can
substitute or tamper with the artifact (registry/MITM/insider, or a CI step
publishing damaged bytes) is undetected at install time. There is **no signing
ceremony** and **no verify gate** — a package is trusted because of where it was
downloaded from, not because of a provable origin.

### Attack surface

1. `scripts/update.sh` — `--url` downloads a `.deb` and installs it (TLS only).
2. `scripts/build-deb.sh` — produces `dist/starship-os_<v>_amd64.deb` with no
   signed artifact output and no signature check.
3. CI (.github/workflows) — no job that rejects unsigned/tampered artifacts.
4. Release chain — no documented key ceremony, so no trust anchor exists.

### Threat

| Attacker | Vector | Impact |
|----------|--------|--------|
| MITM (update download) | Rewrite `.deb` bytes in transit | Arbitrary code as root at update time |
| Registry / mirror compromise | Serve tampered `.deb` | Same as above |
| CI compromise or misstep | Publish damaged/partial `.deb` | Corrupted install, brittle rollback |
| Insider | Replace artifact before distribution | Undetected supply-chain substitution |

### IEC 62443 alignment

- **CR 3.4** (Software update integrity) — packages must be signed and verified
  before install.
- **CR 3.8** (Session integrity) — update transport integrity beyond TLS alone.

## Design: verify-first, ceremony-documented

The update chain gets a **per-artifact detached GPG signature** (a
`<package>.deb.asc` sidecar) verified with `gpgv` against a **pinned, committed
trust anchor** (binary keyring). This is chosen over `debsig-verify` policy
groups (no policy XML; sidecar travels with the artifact) and over `dpkg-sig`
(does not rewrite package bytes into the `.deb`; keeps the artifact byte-for-byte
what CI produced). The **verify** path ships and gates now; the **signing
ceremony** (a human holds the production keys) is documented and executable but
out of scope to run in this ticket — no production key is created here.

### 1. Trust anchor (`security/packages/`)

- `security/packages/starship-release.gpg` — binary keyring carrying the
  *placeholder dev* trust anchor (committed). The verify script defaults to it.
  Documented as REPLACED by the production ceremony; until then updates remain
  admirably-untrusted and verify opt-in.
- `security/packages/README.md` — ceremony vs verify contract, key custody,
  rotation, and how to flip the update chain to enforce signing.

### 2. Verify tool `scripts/verify-deb-signature.sh` (the gate)

```text
scripts/verify-deb-signature.sh [--keyring K] PACKAGE.deb [PACKAGE.deb.asc]
```

- Default keyring `security/packages/starship-release.gpg`; default signature
  sidecar `<package>.asc`.
- Fail-fast: no `gpgv` → exit 3; missing signature → exit 3; missing key →
  exit 1; bad signature / tampered bytes → exit 2. Verify success → exit 0.
- `gpgv` is chosen because it verifies *detached* signatures against a fixed
  keyring with no keyring mutation and no ambient trust (no web-of-trust).

### 3. Signing tool `scripts/sign-deb.sh` (the ceremony executor)

```text
scripts/sign-deb.sh --local-user KEYID PACKAGE.deb
```

- Produces `PACKAGE.deb.asc` via `gpg --detach-sign --armor`. Used today by the
  fixture tests with throwaway keys; used at release time by the human ceremony.

### 4. Update chain wiring `scripts/update.sh`

- New opt-in flag `--verify-signature [KEYRING]`. When set, runs the verify
  tool before `dpkg -i` and **refuses to install** unsigned/tampered packages.
- Off by default until the production ceremony lands, so today's unsigned
  builds keep updating. The README documents the flip to enforce.

### 5. Tests `tests/test_package_signatures.py` (hermetic)

- Generates throwaway GPG keypairs in a temp GNUPGHOME (never commits private
  material), builds a minimal `.deb` fixture, and asserts:
  - unsigned artifact **rejected**,
  - correctly signed artifact **accepted**,
  - tampered artifact **rejected**,
  - signed by an unknown key **rejected**,
  - missing `gpgv` reports an environment error (skips if absent).
- Runs offline, no network, no sudo, no live `/etc` changes.

### 6. CI + nightly gates

- `.github/workflows/ci.yml` new job `verify-package-signature` runs the pytest
  suite — the CI machine fails any PR that presents an unsigned/tampered
  fixture package.
- `scripts/check-nightly.sh` Section 21 asserts the tooling, trust anchor,
  update.sh wiring and fixture tests all exist and pass.

## Non-goals

- No production signing ceremony is executed; no production GPG/cosign key is
  created on this host.
- No live-host package changes (no `dpkg -i`, no `/etc` chmod, no NATS restart).
- No money / publish / new credential domain.
- No repo hosting (apt InRelease) — that is a separate future artifact.
- No `debsig-verify` policy groups or `dpkg-sig` package rewriting.

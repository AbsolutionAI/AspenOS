# ASP-660: Correct stale systemd unit count in nightly baseline table

## Problem

The nightly runbook's baseline table row

```
| systemd unit files | 18 (9 in `systemd/`, 9 in `dist/pkgroot/lib/systemd/system/`) |
```

does not match what is on disk. The runbook's own static-inventory definition (Procedure step 4)
counts `*.service` / `*.timer` / `*.socket`:

```bash
find systemd -maxdepth 1 -type f \( -name '*.service' -o -name '*.timer' -o -name '*.socket' \)
```

which returns 8 files under `systemd/` and 8 under `dist/pkgroot/lib/systemd/system/` — 16 total,
not 18. The "9" appears to be a `.service` count that silently absorbed
`systemd/agnetic-mesh.target`, which is a `.target` and outside the row's own definition.

The units are not missing. Section 20 already states "drop-ins exist for all 8 units" and the
nightly section 6 checks all pass. Only the doc row is stale. Because nightly runs refresh other
rows in this table (python test count, C11 p50 range) but not this one, the drift survives repeated
sweeps.

## Success criteria

- Baseline table row reports `16 (8 in systemd/, 8 in dist/pkgroot/lib/systemd/system/)`.
- The 8 `.service.d` cgroup drop-in dirs are reported on their own row, so the "8 units" figure is
  not misread as covering drop-ins (section 20 counts them per-unit).
- A future nightly run applying the runbook's own `find` command reports no deviation on this row.
- No product code change. No change to `scripts/check-nightly.sh` section 6 or section 20 logic.

## Evidence (2026-09-26, `aspen-os` master)

```
$ find systemd -maxdepth 1 -type f \( -name '*.service' -o -name '*.timer' -o -name '*.socket' \) | wc -l
8
$ find dist/pkgroot/lib/systemd/system -maxdepth 1 -type f \( -name '*.service' -o -name '*.timer' -o -name '*.socket' \) | wc -l
8
$ find systemd -maxdepth 1 -type d -name '*.service.d' | wc -l
8
$ find systemd -maxdepth 1 -type f | sed 's/.*\.//' | sort | uniq -c
      8 service
      1 target      # agnetic-mesh.target — checked by section 6, not a .service
```

The 8 units are identical in both trees: `agnetic-agent@`, `agnetic-dashboard`,
`agnetic-message-history`, `agnetic-nats`, `agnetic-staragent`, `agnetic-status-bridge`,
`starship-fleet`, `starship-health-checker`.

## Implementation

1. Replace the `systemd unit files` baseline row with the verified 16 (8 + 8) figure.
2. Add a `systemd cgroup drop-in dirs` baseline row for the 8 `.service.d` dirs.
3. Add a short note under the baseline table explaining that `systemd/agnetic-mesh.target` is a
   `.target` checked by section 6 and is deliberately excluded from the `.service`/`.timer`/`.socket`
   unit count, so section 6's "9 canonical units" and the baseline's "8 units" are not in conflict.
4. Leave the section 6 / section 20 tables and `scripts/check-nightly.sh` untouched.

- `docs/ops/NIGHTLY_PACKAGING_DEPLOY_CHECK.md` only.
- Out of scope: changing the check script, renaming/adding units, changing the drop-in gate, or
  renumbering any other baseline row.

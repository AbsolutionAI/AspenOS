# ASP-777: ADR-0012 operator-of-record binding implementation (step 2)

**Issue:** [ASP-777](/ASP/issues/ASP-777)
**Parent:** [ASP-802](/ASP/issues/ASP-802) (Biweekly Security Threat-Model refresh)
**Status:** Planned — 2026-11-03
**Base:** `origin/master` + cherry-picked operator registry (ASP-837/ASP-846)

## 1. Problem

ADR-0012 requires that on non-sim plant profiles, every `human_id` in a dual-human
authorization must come from the **operator registry**. Currently
`authorize_gate_request()` accepts any string — any bus peer can inject authorizations
with invented principal IDs, bypassing the operator-of-record requirement.

| Gap | Impact |
|-----|--------|
| Free-string `human_id` in `authorize_gate_request()` | Any bus peer can inject `authorize` with invented IDs and satisfy "two distinct humans" |
| No registry check in `_handle_gate_decision()` | NATS `gate.decision` consumer never validates the principal |
| No audit trail for binding failures | Cannot detect unregistered-operator attempts |

## 2. Design

A single `_check_operator_binding()` helper, called from `authorize_gate_request()`:

```python
def _check_operator_binding(human_id: str, profile: str) -> Optional[str]:
    """Return None if the binding is valid, or a refusal reason string if not.
    
    For light-cell (sim) profiles: always valid (free strings allowed).
    For non-sim profiles: human_id must be enrolled and active in OperatorRegistry.
    """
```

| Decision | Why |
|----------|-----|
| Check at `authorize_gate_request()` not `_handle_gate_decision()` | The handler is in `nats_client.py` which already has a different layer concern; the registry check is authorization policy, not transport |
| Check inside proposal context (profile available) | Need the proposal's `profile` to distinguish sim from non-sim |
| Light-cell passes without check | Sim profiles keep current free-string behavior (ADR-0012 §5) |
| Fail-closed: corrupt or missing registry = refuse for non-sim | A missing registry file on a non-sim profile is a misconfiguration, not a reason to skip the check |
| Audit: `gate.operator_binding.refuse` on failure | Matches existing audit pattern (`gate.refuse`, `gate.authorize.duplicate`) |

## 4. Out of scope

- NATS authorize subject ACLs (ADR-0012 step 3)
- Sentinel/HMI "approve" button → registry resolution (step 4)
- Matrix bot MXID → registry resolution (step 5)
- Physical cell bring-up or motion authorization

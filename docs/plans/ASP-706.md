# ASP-706 — Restore `origin/master` to a green test suite

## Problem

`origin/master` (`4596b7c`) fails its own test suite:

```
1 failed, 466 passed, 3 skipped
FAILED tests/test_holographic_ingest.py::test_explicit_db_env_writes_holographic
ModuleNotFoundError: No module named 'ruamel'
```

`tests/test_holographic_ingest.py:42-45` guards the import of an **out-of-repo** optional
dependency with a *name allowlist*:

```python
except ModuleNotFoundError as exc:
    if "tools.registry" in str(exc) or "holographic" in str(exc):
        pytest.skip("Hermes holographic plugin not available")
    raise
```

Only those two module names skip. Every other unresolvable import re-raises. The Hermes
tree at `/home/tech/.hermes/hermes-agent` imports `ruamel.yaml` from
`hermes_cli/config.py`, so on a host without `ruamel` the failure takes the `raise` path
and turns an absent optional dependency into a hard suite failure.

This is a name allowlist standing in for a capability check. Verified both failure modes:

| Host state | Raised | Old guard skips? |
|---|---|---|
| Hermes tree present, `ruamel` absent (this host) | `No module named 'ruamel'` | **no** → fails |
| Hermes tree absent entirely (a CI runner) | `No module named 'plugins'` | **no** → fails |

CI never caught it: `.github/workflows/ci.yml` runs three *named* test files
(`test_package_signatures.py`, `test_model_digests.py`) and `scripts/smoke-test.sh`, and
none of them runs `tests/` wholesale. Only the nightly check (§13, `no pytest failures`)
and every Aider preflight run the full suite — which is why a red master keeps surfacing
as a mystery regression in unrelated sweeps.

## Scope

The fix and nothing else. The ASP-701 branch also carries the ASP-684 NATS TLS security
work, which is **not** in scope here: its Auditor gate (ASP-703) has not run, and landing
security work from an unapproved gate is exactly the mistake this repo keeps paying for.

## Change

One file, one guard — `tests/test_holographic_ingest.py`:

```python
    except ImportError as exc:
        pytest.skip(f"Hermes holographic plugin not importable: {exc}")
```

`ImportError` rather than `ModuleNotFoundError`: `ModuleNotFoundError` is a subclass of
it, and the outer tree can also fail with a bare `ImportError` (a missing `__init__`
export, a circular import). Every one of those means "the optional external tree is not
usable on this host," which is the condition the `try`/`except` was written to handle.

## Why this does not lose coverage

`assert path.exists()` sits at line 38, **before** the import. A broken dual-write still
raises there and fails the test; it never reaches the `skip`. So the repo-owned assertion
stays load-bearing even when the external read-back is skipped — the skip only drops the
assertion of an out-of-repo plugin's behaviour, which this repository cannot fix.

This matches the convention already in the suite: `tests/test_memory_mcp.py:21-24` and
`tests/test_sentinel_consumer.py:404` skip on an unimportable optional module, and
`tests/test_server.py:5` uses `importorskip`.

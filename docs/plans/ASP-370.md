# ASP-370 — Plan: Apply AUDITOR_BASELINE SSH+UFW (host hardening)

**Issue:** ASP-370 (HIGH, F-021 / H-HOST-01)
**Parent:** ASP-298 — Security Threat Model v2.2
**Status:** Implemented (apply gated on human sudo)
**Date:** 2026-09-21

## 1. Problem

`bt-asp-srv` (control plane) has open host findings:

- `PermitRootLogin yes` — root SSH login enabled.
- `PasswordAuthentication yes` — password auth enabled (brute-force surface).
- No UFW default-deny — incoming is implicitly allowed.

Captain approved the apply window on 2026-09-21
(`CAPTAIN_APPROVED 2026-09-21 — START live SSH+UFW (lockout-safe)`).
This host has **no passwordless sudo**, so the agent lands the apply script +
dry-run tests and the human runs `--apply` with sudo after proof. The agent
never runs `ufw enable` / `sshd` restart itself.

## 2. Decision (recorded)

**Ship a self-guarding apply script whose default mode is `--dry-run`, with a
lockout-safe allowlist gate before any `--apply`.**

| Concern | Decision | Why |
|---------|----------|-----|
| Default mode | `--dry-run` | A plain run must never touch the live host |
| Apply mode | `--apply` requires root + allowlist present in planned ruleset | Prevent lockout on a headless control plane |
| SSH config | Drop-in `/etc/ssh/sshd_config.d/99-aspen-baseline.conf` | Do not clobber the whole `sshd_config`; drop-in is scanned by modern sshd |
| SSH directives | `PermitRootLogin no`, `PasswordAuthentication no`, `PubkeyAuthentication yes`, `AllowUsers` restricted to admin user(s) | F-021 close-off |
| Firewall | UFW default deny incoming + allowlist; explicit allows for lockout ports | F-021 close-off |
| Testing | Hermetic — temp sshd/ufw fixture, no live apply | Guard against the checker itself locking out the host |

### Lockout allowlist (MUST stay reachable)

- SSH `:22` (pubkey only)
- nginx `:443` (Matrix/frozen)
- Paperclip `:3100` on Tailscale `100.78.55.13`
- Hermes dashboard `:8788`
- Buzz `:3000` (Tailscale + loopback)
- Tailscale interface / `100.64.0.0/10`

### SSH drop-in content (template)

```text
# Aspen OS security baseline — managed by apply-auditor-baseline.sh (ASP-370)
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
KbdInteractiveAuthentication no
ChallengeResponseAuthentication no
AllowUsers <ADMIN_USER>
```

`<ADMIN_USER>` defaults to `$SUDO_USER` (or the invoking user) and can be
overridden with the `ASPEN_SSH_ALLOW_USERS` env var (space-separated).

### UFW planned rules (in `--apply` order)

```text
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp                      # SSH (pubkey)
ufw allow 443/tcp                     # nginx (Matrix/frozen)
ufw allow from 100.64.0.0/10 to any port 3100 proto tcp   # Paperclip on Tailscale
ufw allow 8788/tcp                    # Hermes dashboard
ufw allow from 100.64.0.0/10 to any port 3000 proto tcp   # Buzz on Tailscale
ufw allow in on tailscale0            # Tailscale interface
```

`--apply` refuses to run unless every allowlist port appears in the planned
ruleset (the allowlist gate). `ufw enable` and `sshd reload` are printed as
the human's final two sudo steps, never executed by the script.

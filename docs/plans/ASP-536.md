# ASP-536: NATS accounts — aspen.* subject ACL + credential hardening

## Problem

H-013 (threat model v2.2): `fleet-accounts.conf` only restricts `starship.*` / `agnetic.*`.
The `aspen.*` namespace (ADR-0007 / ADR-0003) is unguarded:

- `STARSHIP_OPS` user has **no permissions block** → open-by-default; a compromised
  ops credential can publish arbitrary `aspen.fleet.mission.*` / `aspen.safety.*`.
- Edge / range users never get `aspen.*` allows, so plants cannot use the
  ADR-0007 subject contract either (no positive path).
- H-011: credentials embedded as plaintext passwords in the materialized conf;
  generator writes nkey as a *sibling* entry, so plaintext password always remains.
- `fleet-auth.yaml` / `subjects.yaml` lack `aspen.*` rows (docs drift).

## Solution

1. **ACL allow lists (template + generator):** add explicit `aspen.*` publish/subscribe
   allows per role in `nats/fleet-accounts.conf.tmpl`:
   - ops: `aspen.sentinel.>`, `aspen.authz.>`, `aspen.fleet.>`, `aspen.safety.>`
     (+ existing `starship.>`, `agnetic.>` — now enumerated, no longer open-by-default)
   - edge: publish `aspen.fleet.>`, `aspen.edge.>`, `aspen.safety.estop`,
     `aspen.safety.authorize_clear`; subscribe `aspen.fleet.>`, `aspen.edge.>`,
     `aspen.safety.estop`, `aspen.safety.clear`, `aspen.sentinel.>`
   - red: publish `aspen.fleet.node.*` heartbeats, `aspen.edge.>`; subscribe
     `aspen.fleet.>`, `aspen.safety.estop`
   - blue: publish `aspen.fleet.>`, `aspen.edge.>`; subscribe existing + `aspen.fleet.>`,
     `aspen.safety.estop`, `aspen.sentinel.fleet.overview`
   - telem: unchanged (publish-only telemetry, no `aspen.*`)
   Guards match ADR-0003 fleet/edge/safety semantics (estop fanout "all RRMs",
   `authorize_clear` never unlatches alone).

2. **Credentials — nkey-only by default:** `scripts/gen-nats-accounts.sh` now
   emits an **nkey-only user entry** (`{nkey: "U…"}`) whenever the `nk` binary is
   available — the plaintext `password:` field is dropped from the conf entirely,
   and per-role creds files carry the seed (mode 600). `--password-only` forces the
   legacy fallback. Existing parent-run .env files stay `chmod 600`.

3. **Docs drift:** register the `aspen.*` tree in `nats/subjects.yaml`; mirror the new
   allows in `nats/fleet-auth.yaml` role blocks.

## Files to modify (tracked)

1. `nats/fleet-accounts.conf.tmpl`
2. `scripts/gen-nats-accounts.sh`
3. `nats/fleet-auth.yaml`
4. `nats/subjects.yaml`

## Verification

- Regenerate into a scratch `--out` dir in both modes (password-only and nkey mocks);
  `nats-server -c` parse both materialized configs (regression: config still valid).
- Assert `starship.*` / `agnetic.*` allow entries byte-identical between before/after
  (regression criterion: existing permissions unchanged).
- Grep materialized conf for `password:` — must be absent in nkey mode (except `sys` admin).
- `python3 -c` yaml-load `fleet-auth.yaml` and `subjects.yaml`.
- Commit only the 4 tracked files (the materialized conf / creds stay gitignored).

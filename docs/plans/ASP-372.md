## Problem

Manufacturing cell hosts today get firewall treatment ad hoc: per-host UFW
grants decided at install time, not versioned, not protocol-aware, and with no
audit-coupled ruleset. When industrial protocol drivers (MQTT, OPC-UA,
ROS2/DDS) are deployed, there is no agreed default-deny cell-perimeter ruleset
to ship with the cell — so either nothing is applied at the perimeter, or an
ad-hoc allow-all gets baked in. F-008 of the ASP-298 refresh requires a
**draft, versioned, protocol-aware cell firewall template set** to be the
starting point for any future cell commissioning.

### Attack surface

1. Cell PLC/RTU/robot nodes reachable from plant VLAN with no default-deny.
2. Cleartext MQTT (1883) crossing the cell perimeter.
3. OPC-UA discovery multicast escaping the cell (endpoint enumeration).
4. ROS2/DDS ephemeral UDP range (49152-65535) leaking across the perimeter.

### Threat

| Attacker | Vector | Impact |
|----------|--------|--------|
| Compromised plant host | Reaches cell PLC/RTU/robot over open ports | Process manipulation / data integrity loss |
| OT eavesdropper | Cleartext MQTT on the plant VLAN | Telemetry disclosure, command replay |
| Rogue OT device | OPC-UA discovery broadcast | Cell inventory disclosure |
| Rogue node | DDS multicast/unicast leakage | Cell lateral movement |

### IEC 62443 alignment

- **SR 5.1** (Zone segmentation) — cell perimeter default-deny.
- **SR 5.3** (Boundary protection) — defence-in-depth: firewall + app-layer
  security (TLS MQTT, OPC-UA sign-and-encrypt, DDS Security).
- **EU GMP Annex 11 / 21 CFR Part 11** — audit-table logging and
  version-controlled rulesets.

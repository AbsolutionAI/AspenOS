# ASP-597: Sentinel `fleet.overview` producer (ADR-0007 residual)

## Problem

ADR-0007 defines `aspen.sentinel.fleet.overview` — "aggregate plants/nodes/status,
`degraded[]`" with fan-in from the fleet heartbeat. The audit path
(`aspen.sentinel.audit.event`) has a publisher (ASP-537) and a consumer (ASP-566)
behind the dashboard, but the overview is still a **stub**:

- `src/python/sentinel/consumer.py` returns `_stub: true` previews and its docstring
  explicitly says "The producer for `aspen.sentinel.fleet.overview` does not yet exist".
- `dashboard/server.py` `/api/sentinel/overview` therefore returns stub data.

No code publishes to `aspen.sentinel.fleet.overview` anywhere in the monorepo or the
sibling plant packages (confirmed by FLEET_SUBJECT_PUBLISHERS.md inventory, ASP-596).

## Success criteria (DoD)

- Producer emits aggregate plants/nodes/status (`degraded[]`) on
  `aspen.sentinel.fleet.overview` (JetStream) with a durable JSONL journal fallback
  (same offline-first contract as the audit publisher).
- Fan-in comes from the existing `aspen.fleet.node.heartbeat` (+ `register` /
  `ops.status` best-effort) subjects, not from new heartbeat sources.
- Dashboard consumer path verified: `/api/sentinel/overview` returns real producer
  data when available and only falls back to the local preview when no producer
  data exists.
- Sim-only; no physical plants involved.
- Flash-only: Aider QA then Auditor before `done`.

## Solution

### 1. New `src/python/sentinel/fleet_overview.py` — `FleetOverviewProducer`

- Constants: `SUBJECT_FLEET_OVERVIEW = "aspen.sentinel.fleet.overview"`,
  `DEFAULT_OVERVIEW_LOG = "/var/lib/aspen/sentinel/fleet-overview.jsonl"`
  (env `ASPEN_FLEET_OVERVIEW_LOG`), `DEFAULT_INTERVAL_SECONDS = 30`,
  `DEFAULT_STALE_AFTER_SECONDS = 70` (heartbeat interval is 30s by default, so a
  node that misses ≥2 heartbeats is degraded).
- Fan-in subjects: `aspen.fleet.node.heartbeat`, `aspen.fleet.node.register`,
  `aspen.fleet.ops.status` (nodes record/refresh registry; ops status merges plant
  + exercise context when present).
- In-memory node registry keyed by `node_id` with `{plant, roles, team, status,
  last_seen, capabilities}`.
- `build_overview()` → aggregate dict:
  - `overview_id` (uuid4 hex — used as `Nats-Msg-Id`),
  - `ts` (UTC ISO-8601),
  - `source = "sentinel-fleet-overview"`,
  - `status` (`offline` if no nodes known, `degraded` if any node stale or not
    online, else `ok`),
  - `total_nodes`, `nodes[]` (each with status), `plants[]` (id + aggregated
    status + node count), `degraded[]` (node ids).
- Journal append is **unconditional** (append + flush + fsync); JetStream publish
  is **best-effort** (online `publish_now()`; offline events still journaled).
- `start()` connects best-effort, ensures the `ASPEN_SENTINEL` stream (idempotent),
  subscribes to the fan-in subjects; `run_loop()` publishes every interval;
  `publish_now()` emits one aggregate; `close()` drains.
- `latest()` / `tail(n)` read back from the journal (CLI + consumer fallback).
- Env honors: `ASPEN_NATS_URL`, `ASPEN_FLEET_OVERVIEW_LOG`, `ASPEN_FLEET_OVERVIEW_INTERVAL`,
  `ASPEN_FLEET_OVERVIEW_STALE_AFTER`.

No replay/backfill: old snapshots are stale by definition; the journal is a
durability + offline read record, and the consumer always prefers the newest.

### 2. CLI `scripts/sentinel-fleet-overview.py`

- `emit` — build + journal + best-effort publish one overview, print as JSON.
- `daemon` — `start()` + `run_loop()` (fan-in subscription + periodic publish).
- `tail [-n N] [--json]` — newest journal overviews.
- `check` — report journal + stream + registry state.
- No `nats` import at module load; broker-only paths import lazily (audit CLI parity).

### 3. Consumer wiring (`src/python/sentinel/consumer.py`)

- Subscribe to `aspen.sentinel.fleet.overview` in `start()` (same live ring pattern
  as audit events); keep dedup + ring buffer behavior.
- `fleet_overview()` becomes: live NATS overview (newest) → producer journal
  (newest, `ASPEN_FLEET_OVERVIEW_LOG`) → local preview fallback (existing stub,
  marked `_stub: true`). The dashboard route stays untouched — it already calls
  `consumer.fleet_overview()`.

### 4. Package export (`src/python/sentinel/__init__.py`)

Add `FleetOverviewProducer`, `SUBJECT_FLEET_OVERVIEW`, helpers to `__all__`.

### 5. Tests `tests/test_sentinel_fleet_overview.py`

- `build_overview` shape: plants/nodes/status/degraded[] present; `overview_id`,
  `ts`, `source`.
- Staleness: a node whose `last_seen` is older than `stale_after_seconds` lands in
  `degraded[]`; overall `status` degrades; unknown registry → `offline`.
- Registry ingest from heartbeat / register payloads.
- Journal: `emit` appends fsync'd JSONL; `latest()` / `tail()` read it back.
- NATS publish (mocked): subject + `Nats-Msg-Id` header + stream name; offline
  publish does not raise.
- Consumer: `fleet_overview()` returns producer-journal aggregate when present and
  preview stub when absent; live overview message feeds the ring.
- Existing `test_sentinel_consumer.py` / `test_sentinel_audit.py` remain green.

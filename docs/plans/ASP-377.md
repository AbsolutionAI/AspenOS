# ASP-377 — F-013: Model Hash Pinning / Signature Verification

**Parent:** ASP-298 (Biweekly Security Threat-Model refresh)
**Author:** Auditor
**Priority:** Low (F-013 per threat model v2.2)
**Status:** Implemented — see "Implementation note" below; ready for Aider QA
**Threat model:** `docs/SECURITY_THREAT_MODEL_v2.2.md` §2.3 F-013

## Problem

All Ollama models in the Aspen OS fleet are pulled by **tag-only** (`:latest` or
version tags). Tags are mutable pointers — the content at a given tag can change
without notice if the upstream registry is compromised, a man-in-the-middle
intercepts the pull, or a registry account is hijacked. This is a supply-chain
integrity gap.

### Attack surface

1. **`config/models.yaml`** — Specifies models by tag name (e.g.
   `jeffgreen311/Eve-V2-Unleashed-...:latest`). No digest pins.

2. **`config/models/Eve-V2-Unleashed.Modelfile`** — `FROM` directive uses
   `:latest` tag. No digest pin.

3. **`scripts/install-models.sh`** — `ollama pull $m` with no digest checking.
   Error exit logged but pull accepted silently.

4. **`scripts/agent-health-checker.py`** — `try_pull_model()` calls
   `ollama pull <model_name>` without digest verification.

5. **`dashboard/server.py`** — `handle_api_ollama_pull` endpoint allows
   ad-hoc pulls by name only.

6. **`packaging/install-starship.sh`** — `ollama pull` with tags.

### Threat

| Attacker | Vector | Impact |
|----------|--------|--------|
| Registry compromise | Push malicious blob under same tag | Model poisoning, RCE via abliterated/replaced model |
| MITM (pull) | Rewrite registry response | Same as above |
| Dependency confusion | Register malicious namespace matching internal pattern | Supply-chain substitution |
| Insider | Replace model on disk between pull and verification | Tampered runtime model |

### IEC 62443 alignment

- **CR 3.4** (Software update integrity) — model updates must be signed or
  integrity-verified before loading.
- **CR 5.1** (Patch management) — models are runtime components subject to
  version/digest tracking.

## Design

### 1. Resolve digests at build/install time

Add a script `scripts/resolve-model-digests.py` that:

- Reads `config/models.yaml`
- For each model entry with `upstream: <name>`, calls `ollama list --digests`
  or inspects `~/.ollama/models/blobs/` to resolve the SHA256 digest
- Outputs a pinned `config/models-digests.yaml` with digests embedded:

```yaml
models:
  Eve-V2-Unleashed:
    upstream: jeffgreen311/Eve-V2-Unleashed-...@sha256:a1b2c3d4...
    alias: Eve-V2-Unleashed
    digest: sha256:a1b2c3d4...
    # ...
```

### 2. Digest-verified pull

Modify `scripts/install-models.sh`:

- Read digest from `models-digests.yaml` (fall back to `models.yaml` for
  development)
- Pull using `upstream` (tag-only if no digest available)
- After pull, verify `ollama show --digests <model>` matches the pinned digest
- Fail-hard if digest mismatch (reject `WARN` fallback)

```bash
digest=$(python3 -c "import yaml; ...")
ollama pull "$upstream"
actual=$(ollama show --digests "$alias" | grep 'SHA256' | awk '{print $2}')
if [ "$actual" != "$digest" ]; then
  echo "FATAL: Digest mismatch for $model — expected $digest, got $actual" >&2
  exit 1
fi
```

### 3. Modelfile digest pin

Update `config/models/Eve-V2-Unleashed.Modelfile`:

Replace:
```
FROM jeffgreen311/Eve-V2-Unleashed-...:latest
```
With:
```
FROM jeffgreen311/Eve-V2-Unleashed-...@sha256:<resolved-digest>
```

### 4. Health checker digest guard

Modify `scripts/agent-health-checker.py` `try_pull_model()` to:

- Resolve the expected digest from `models-digests.yaml`
- After pull, run `ollama show --digests` to compare
- Reject the pull on mismatch (do not load tampered model)
- Log a security event on mismatch

### 5. API guard

Modify `dashboard/server.py` `handle_api_ollama_pull`:

- Require a `digest` parameter for production mode
- Reject pulls without digest verification in production
- Log digest-verified vs unverified pulls for audit

### 6. CI gate (optional, stretch)

Add a CI step `security-model-digests` that:

- Runs `scripts/resolve-model-digests.py --check`
- Fails if any model in `models-digests.yaml` has a stale/mismatched digest
  (tracks registry drift)

## Implementation note (2026-09-21, verified on ollama 0.32.11)

`@sha256:<digest>` references are **rejected by this fleet's Ollama build at
pull and create time**:

- `ollama pull <name>:<tag>@sha256:<x>` → `Error: 400 Bad Request: invalid model name`
- `ollama pull <name>@sha256:<x>` (bare, no tag) → same error
- `ollama show <name>@sha256:<x>` → same error
- Modelfile `FROM <name>:<tag>@sha256:<x>` + `ollama create` → same error
- Verified against both the locally-stored manifest digest and the live
  registry manifest digest from `registry.ollama.ai`.

The digest reported by `/api/tags` (and `ollama list` "ID") **is** the sha256 of
the local OCI manifest document
(`sha256` of `~/.ollama/models/manifests/registry.ollama.ai/.../<tag>`),
so it is a stable, content-derived identifier for a model revision.

### Adjusted design (enforcement via post-pull verification)

Digest-pinned ref pulls are unavailable, so F-013 enforcement is:

1. **Pin**: `scripts/resolve-model-digests.py` reads `config/models.yaml` and
   emits `config/models-digests.yaml` with the sha256 of each locally-present
   model revision. Models not present locally are recorded with `digest: null`
   (unpinned) — pins are established on a cell when the model is first pulled
   and verified.
2. **Verify-after-pull (fail-hard)**: `install-models.sh` pulls by tag, then
   compares the pulled model's `/api/tags` digest against the pin. Mismatch →
   `FATAL`, exit 1. No pin → `WARN` (dev mode).
3. **Refuse-to-load**: `agent-health-checker.py` resolves the expected digest
   before auto-pull, verifies after pull, logs a `SECURITY
   model-digest-mismatch` event on mismatch, marks the model unavailable, and
   does **not** auto-fix a tampered model.
4. **API guard**: `dashboard/server.py` requires the caller to pass a digest
   that matches the pin when a pin exists (and hard-requires one under
   `STARSHIP_ENV=production`); it verifies post-pull and removes + logs a
   security event on mismatch.
5. **Modelfile**: `FROM` keeps the `:latest` tag (a `@sha256:` FROM is rejected
   by `ollama create` on 0.32.11); the header documents the pinned digest and
   points at `config/models-digests.yaml` as the single source of truth.

Deviation from the original "Modelfile FROM @sha256:" acceptance item is
required by the runtime — the enforceable equivalent is the install-time
fail-hard verify. This is flagged for Architect review.

## Implementation complete (2026-09-21, Opencode)

Delivered per the above design, with two tightening decisions:

1. **Registry-authoritative pins.** Unlike the original draft (local-only
   `/api/tags`), `scripts/resolve-model-digests.py` resolves pins from the
   `registry.ollama.ai` manifest API first and falls back to the local store.
   This keeps the committed `config/models-digests.yaml` correct on fresh cells
   and lets the `security-model-digests` CI gate run deterministically
   (`--check --offline`), while `--check` online still fails on registry drift.
2. **Canonical digests.** `/api/tags` on this fleet returns bare-hex digests
   (no `sha256:` prefix) while pins are canonicalized. All three consumers
   (install-models.sh via the resolver, agent-health-checker.py, dashboard)
   canonicalize before comparing, so a pinned revision never false-flags as
   tampered — and a truly tampered revision still fails hard.

Deliverables:
- `scripts/resolve-model-digests.py` — resolve / `--check` / `--digest` /
  `--verify-local` (single source of truth for pins)
- `config/models-digests.yaml` — pins for all 7 models in config/models.yaml
- `scripts/install-models.sh` — pulls by tag, then `--verify-local` fail-hard;
  dev WARN when unpinned, FATAL under `STARSHIP_STRICT_DIGESTS=1`
- `config/models/Eve-V2-Unleashed.Modelfile` — `:latest` kept (runtime rejects
  `@sha256:`), header documents the pin + source of truth
- `scripts/agent-health-checker.py` — pins loaded at startup; refuses to load a
  missing/tampered revision (`SECURITY MODEL-DIGEST-MISMATCH`), no auto-fix of
  tampered models
- `dashboard/server.py` — production mode requires a digest matching the pin;
  verifies after pull and removes a tampered model; audit log for unverified
  dev pulls
- `packaging/install-starship.sh` — no longer swallows install-models exit
- `tests/test_model_digests.py` (20 tests, hermetic), CI
  `security-model-digests` job, nightly Section 22

Verification: full suite `python3 -m pytest tests/ -q` passes; resolver
`--check` (offline + live registry) passes; `bash -n` + ruff clean.

## Rejected alternatives

- **Cosign/signature verification** — Overkill for local Ollama models. Digest
  pinning provides integrity; signatures add key-management complexity without
  a clear distribution channel for detached sigs.
- **Sidecar checksum file** — Redundant with Ollama-native `@sha256:` support.
  A single source of truth (`models-digests.yaml`) is cleaner.
- **Air-gapped only** — Doesn't address the tag-hijack vector during initial
  pull.
